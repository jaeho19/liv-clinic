# 운영 권고안 — 유입 통계 / 위챗 응대 / 에이전시 연계 (2026-06)

> 2026-06-18 운영 회의록 기반. 홈페이지(어드민)에 **유입 통계 기능**을 구축하면서, 코드로 해결되지 않는 **비즈니스/운영 결정** 항목을 정리한 문서입니다. 통계 데이터를 어떻게 의사결정에 연결하는지 함께 제안합니다.

## 0. 이번에 구축된 것 (개발 완료)
- **어드민 → 유입 통계** 메뉴(`/admin/inflow`) 신설.
  - **일일 입력 탭**: 리드(문의) 1건 = 1행. 채널(위챗·카카오·네이버·전화·워크인·홈페이지·라이브챗·기타), 에이전시명, 신규/재진, 이름·위챗ID·카카오ID·전화, 시술, 예약/내원 체크(+날짜), 비고. 날짜 이동·전기간 검색·CSV 내보내기.
  - **통계 탭**: 기간(7/30/90일·이번 달) 필터, KPI(신규 연락·예약·내원·전환율), 전환 퍼널, 채널별 신규 연락, **에이전시 vs 직접 유입**, 일자별 추세.
- DB: `inflow_leads` 테이블(`inflow-leads-table.sql`). **인증된 관리자만 접근(RLS)**.
- 라이브챗(zh) 인트로에 **직접 예약 프로모션 배너**(5% 할인/사은품) 노출.

이 데이터가 아래 1~3번 비즈니스 결정의 **근거 자료**가 됩니다.

## 1. 에이전시(바이올렛) 귀속 기준 — *확정(최초 유입 기준 고정)*

> **결정**: "최초 유입 기준 고정"을 공식 기준으로 채택한다. (가장 명확해 내부 분쟁 최소화. 일일 입력 가이드도 동일 기준으로 작성됨.)

**배경 문제**: 우리 병원 위챗으로 최초 문의한 환자를 외부 채널(바이올렛)로 넘긴 정황 제보. 재진 환자를 에이전시 공로로 인정할지(몇 회까지) 기준이 모호 → 아래 기준으로 일원화한다.

### 1-1. 확정 기준 — 최초 유입 기준 고정
- **귀속 판단은 "최초 문의 시점"으로 한 번만 정하고, 이후 바꾸지 않는다.**
  - 최초 문의가 **우리 채널**(위챗·홈페이지·전화·워크인 등)이면 → **직접 유입**. 이후 재진·재방문도 계속 직접.
  - 최초 문의가 **에이전시 소개**면 → 해당 **에이전시 귀속**. 이후 재진·재방문도 같은 에이전시로 유지.
- 데이터 적용: `inflow_leads`에서 동일 환자(위챗ID/카카오ID/전화 기준)의 **첫 `contact_date` 행의 `channel`/`agency`**를 귀속 기준으로 삼는다. 신규 입력 시 직원은 이 규칙대로 `에이전시`·`구분(신규/재진)`을 채운다.

> 참고로 검토했던 대안 — **B. 시술 후 N회까지만 에이전시 인정**, **C. 케이스별 실장 협의** — 은 운영 부담·분쟁 소지가 커 채택하지 않음. 향후 정산 데이터로 재검토 가능.

### 1-2. 재발 방지 내부 원칙
- **우리 채널로 첫 문의가 들어온 환자는 외부 에이전시로 넘기지 않는다**(회의의 "우리 쪽으로 해달라" 원칙 명문화).
- 위챗 응대를 특정 인력이 독점하지 않도록 공동 응대·권한 분리(§3와 연계).

### 1-3. 선결 과제 — 제보 사실관계 확인 (체크리스트)
- [ ] 제보 대상 환자 특정 (위챗ID/이름/문의일)
- [ ] 최초 문의 채널이 우리 위챗이었는지 대화·기록으로 확인 (추정 금지)
- [ ] 누가 어떤 경로로 바이올렛에 넘겼는지 경위 확인
- [ ] 위 1-2 원칙 위반 여부 판단 → 결과를 본 문서에 기록

### 1-4. 측정·검증
통계 탭 **"에이전시 vs 직접 유입" + 신규/재진**으로 월별 에이전시 귀속 비중·내원 전환을 추적해 기준의 타당성을 사후 검증한다. 분쟁 발생 시 `inflow_leads` 기록으로 판정.

**액션**: 남실장·방 포함 기준 검토 미팅(~2026-06-24)에서 위 1-1 기준을 공지·승인하고, 1-3 제보 확인 결과를 반영한다.

## 2. 인센티브 산정 기준 변경 (에이전시 fee 차감 후) — *합의됨 / 변경안*

**합의**: 인센티브를 "총매출"이 아닌 **"에이전시 fee 차감 후 순매출"** 기준으로 변경.

### 2-1. 계산식
```
인센 베이스 = 시술 매출 − 에이전시 fee
에이전시 fee = 시술 매출 × 에이전시 수수료율(%)   (직접 유입은 fee = 0)
인센티브 = 인센 베이스 × 인센율(%)
```
> 귀속(누가 에이전시 건인지)은 §1의 "최초 유입 기준 고정"을 따른다. 직접 유입 건은 fee 0 → 인센 베이스 = 시술 매출 전액.

### 2-2. 예시 비교 (인센율 10% 가정)
| 구분 | 시술 매출 | 에이전시 fee | 인센 베이스 | 기존 인센(총매출 10%) | 변경 인센(순매출 10%) |
|---|--:|--:|--:|--:|--:|
| 에이전시 건 (수수료 30%) | 1,000,000 | 300,000 | 700,000 | 100,000 | **70,000** |
| 에이전시 건 (수수료 20%) | 1,000,000 | 200,000 | 800,000 | 100,000 | **80,000** |
| 직접 유입 건 (fee 0) | 1,000,000 | 0 | 1,000,000 | 100,000 | **100,000** |

→ **동일 매출이라도 에이전시 건일수록 인센이 줄고, 직접 유입일수록 인센이 큼.** 직접 유입 확대(§4 라이브챗 프로모션)와 동기가 정합한다.

### 2-3. 확정 필요 항목 (내부 결정)
| 항목 | 내용 | 값(미정) |
|---|---|---|
| 인센율 | 순매출에 적용할 % | ___% |
| 에이전시 수수료율 | 에이전시/계약별 fee % | 바이올렛 ___% / 기타 ___% |
| 시행일 | 적용 시작 시점 | 2026-__-__ (7월/8월?) |
| 적용 대상 | 방 등 대상자, 소급 여부 | ________ |
| 산정 주기 | 월 정산 등 | 월 1회 |
| 형평 처리 | 직접 유입(fee 0) 우대 폭 점검 | ________ |

### 2-4. 후속
- 위 표의 빈 값(인센율·수수료율·시행일·대상)을 확정하면 본 문서를 갱신하고, **대상자 개별 통보 + 계약/규정 업데이트**를 진행한다.
- (선택·개발) 유입 통계에 매출·fee 입력 필드를 추가하면 "fee 차감 후 인센 베이스"를 자동 집계할 수 있음 — 필요 시 별도 요청.

**액션**: 변경안 확정(~2026-06-26) — 위 2-3 값 채우기 + 적용 대상·시행일 통보.

## 3. 위챗 응대 분산 · PC 접근 · 번역 워크플로우 — *조사/정립 필요*
**문제**: 위챗 응대가 특정 인력/외부 채널에 집중. 데스크톱 접근·번역으로 공동 응대해 의존도 완화 필요.

**권고**:
- **PC 접근**: WeChat 데스크톱 클라이언트 또는 **WeChat Work(企业微信)** 도입 검토(웹/PC 다중 상담원·권한 분리·기록). 개인 위챗은 PC 다중 로그인 제약이 큼 → 장기적으로 기업용 전환 권장.
- **번역**: 중국어 전담이 없어도 응대 가능하도록, 홈페이지 **라이브챗(자동 번역)으로 유도**(이미 zh↔ko 자동번역 지원). 위챗 신규 문의에 라이브챗/홈페이지 예약 링크를 안내.
- **권한/보고 체계**: 응대 인력(안·방·이연·정연) 역할·보기 권한·당번/백업 규정 문서화. 일일 입력 책임자 교대표 포함.

**측정 연결**: 채널별 신규 연락에서 위챗 비중·라이브챗 비중 변화를 추적해 분산 효과 확인.

## 4. 라이브챗 직접 예약 프로모션 파일럿 — *구현됨(zh 배너), 운영 설계 필요*
**구현**: 중국어 라이브챗 인트로에 "직접 예약 시 5% 할인/사은품" 배너 노출(`ChatPanel`, i18n `chat.promoTitle/promoBody`).

**운영 설계 (확정 필요)**:
- **조건**: 할인율(5%)·사은품 종류·중복 적용 여부·유효기간.
- **검증/정산**: 라이브챗 경유 예약을 `inflow_leads`에서 `channel=livechat`로 기록 → 내원·매출과 대조해 효과 측정.
- **중국어 UX 조사**: 대상 고객(중국)에게 라이브챗 수용성/편의 의견 수렴 후 정식화.
- **기대효과**: 직접 유입 증가 → 에이전시 fee 절감(§2 인센 베이스 확대와 정합).

**액션**: 파일럿안(비용·효과 추정 포함) 작성(회의록 마감 2026-06-28).

## 5. 일일 입력 운영 규칙 (권고)
- **입력 시점**: 매일 마감 정산 시 당일 신규 연락 일괄 입력, 예약/내원은 발생 시 해당 리드에 체크.
- **책임자**: 안·방·이연·정연 교대(주 단위 당번 + 백업). 누락 방지 위해 마감 체크리스트에 "유입 통계 입력" 포함.
- **품질**: 동일 환자 중복 행 방지(검색으로 기존 리드 확인 후 예약/내원 체크). 위챗ID/전화를 식별자로 일관 기입.
