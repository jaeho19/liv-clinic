너는 시니어 풀스택 엔지니어 겸 프로덕트 엔지니어다.
내가 운영 중인 병원 홈페이지 관리자 페이지(좌측 메뉴: 대시보드/상담관리/이벤트관리/팝업관리)에 “병원 운영 OS” 기능을 추가하려고 한다.
현재 상담관리는 리드 리스트(이름/전화/시술/상태/메모/접수일/출처)와 상태 변경, 검색, CSV 다운로드가 있다.
목표는 “상담(리드) → 팔로업 → 내원/케이스(운영) → 재고 차감 → 성과 대시보드”로 연결되는 내부 운영 시스템을 만드는 것이다.
전자차트(보험/DUR 연동)는 건드리지 않고, 별도의 운영 DB/대시보드를 관리자 페이지에 붙인다.

아래 요구사항을 만족하는 설계와 구현을 제안하고, 가능한 범위는 실제 코드까지 생성해라.
질문은 꼭 필요한 것만 최소로 하고, 기본값은 합리적으로 가정해 진행해라.

[1) 우선순위 및 MVP 단계]
- 2주 MVP: 상담관리 확장(팔로업 중심)
  - 상담(리드) 필드 추가: 담당자(assignee), 다음 연락 예정(next_followup_at), 연락 결과(outcome), 관심 시술 태그(procedure_tags[]), 예상 예산(budget_range), 내원 가능 요일(availability)
  - 상태 세분화: 콜백 예정/부재중/재연락/예약확정/노쇼/완료/취소
  - “오늘 콜백해야 할 목록(Today’s tasks)” 화면/필터 제공
- 4~6주: 운영 타임라인(화이트보드 형태)
  - 케이스 카드가 단계 이동: 대기 → 마취 → 시술 → 관리 → 종료
  - 버튼 2~3개로 타임스탬프 기록: 마취 시작/종료, 시술 시작/종료, 관리 시작/종료
  - 상담 리드에서 “케이스 생성” 버튼으로 전환
- 8~12주: 재고 자동 차감 + 리포트
  - 시술(프로시저) 선택 시 재고 레시피에 따라 자동 차감
  - reorder_point 이하 경고(배지/표시)
  - 시술별 평균 소요시간, 평균 매출, 시간당 매출 리포트(간단)
- 후순위: 안전 체크리스트(정품 스티커/주의사항/알러지 등), 마케팅(출처별 전환율/구글 리뷰 요청 관리)

[2) UI/메뉴 추가 제안]
좌측 메뉴를 다음처럼 확장:
- 대시보드
- 상담관리(리드)
- 운영현황(타임라인)
- 재고관리
- 리포트(전환/효율)
- 설정(시술 마스터/직원 권한)
기존 이벤트관리/팝업관리 유지.

[3) DB 설계(최소 테이블)]
아래 테이블 구조를 제안하고, Prisma/Supabase SQL 등 한 가지로 실제 스키마를 만들어라.
- leads: name, phone, procedure_tags[], source, status, memo, assignee, next_followup_at, created_at
- cases: lead_id, visit_date, doctor, room, state, timestamps(마취/시술/관리 시작/종료), created_at
- procedures: name, default_duration_min, price_default(optional), recipe(json)
- inventory_items: name, unit, on_hand, reorder_point, expiry_date(optional)
- inventory_tx: case_id, item_id, qty, tx_type(사용/입고/폐기), created_at
- audit_log: actor, entity, entity_id, action, before/after, created_at

[4) 보안/권한/로그]
- 주민번호/진단명/상세 의무기록은 저장하지 않는다(운영 데이터만).
- 역할 기반 권한: owner/admin/staff 정도로 구분.
- 모든 변경은 audit_log에 남긴다.
- 개인정보(전화번호 등)는 최소 수집/마스킹 옵션 고려.

[5) 기술 스택 제안 + 코드 산출]
- 프론트는 React/Next.js 또는 현재 관리자 페이지 스택에 맞춰 제안.
- DB는 Supabase(Postgres) 또는 SQLite+Prisma 등으로 제안.
- 인증은 간단한 이메일/비번 또는 Supabase Auth로 제안.
- 관리자 화면은 테이블+필터+상태 드롭다운+메모 인라인 편집 형태 유지.
- 구현물:
  1) 프로젝트 폴더 구조
  2) DB 스키마/마이그레이션
  3) 핵심 API (CRUD: leads, cases, inventory)
  4) 상담관리 화면 확장(필드/상태/오늘 콜백)
  5) 운영현황(타임라인) 기본 화면
  6) 재고 차감 로직(프로시저 recipe 기반)
  7) 최소 리포트(시술별 평균 시간, 시간당 매출)

[6) 동작 예시(필수)]
- 리드 생성(웹사이트 폼) → 상담관리 리스트에 표시
- 상담 상태를 “콜백 예정”으로 바꾸고 next_followup_at 설정
- 오늘 콜백 화면에서 해당 리드가 자동 노출
- “케이스 생성” 누르면 cases가 생성되고 운영현황 보드에 카드 표시
- “시술 종료” 누르면 해당 케이스에 연결된 프로시저 기준으로 inventory_tx 자동 생성 및 재고 차감
- 재고가 reorder_point 아래면 재고관리에서 경고 표시

위 요구사항대로,
1) 아키텍처/데이터모델/UI 와이어프레임(텍스트) 제시
2) 스택 선택 근거 및 단계별 구현 계획
3) 가능한 범위의 실제 코드(최소 작동)까지 생성해라.
