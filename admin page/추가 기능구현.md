# 결론부터 정리

이 병원에 필요한 것은  
❌ _“전자차트 대체 시스템”_ 이 아닙니다.  
⭕ **전자차트 위에 얹는 ‘운영 의사결정용 내부 소프트웨어’** 입니다.

즉,

> **진료는 기존 전자차트로 하고,  
> 병원은 ‘별도의 운영 OS’로 관리하는 구조**

가 가장 합리적입니다.

---

# 1. 왜 기존 프로그램으로는 안 되는가 (문서 근거 기반)

두 회의록에서 반복적으로 드러난 문제는 아래 4가지입니다.

## ① 데이터는 있는데 “보이지 않음”

- 매출, 재고, 시술 시간, 대기시간, 직원 투입
    
- → 엑셀·수기·머릿속에 흩어져 있음
    
- → **판단이 감각에 의존**
    

## ② 실수가 구조적으로 발생

- 주의사항 전달 누락
    
- 정품 스티커, 사후관리, 금기 시술 체크 누락
    
- 바쁜 날에는 “알면서도 놓침”
    

## ③ 사람을 늘리기 전에 ‘카파(capacity)’를 모름

- 의사 1명 추가 시:
    
    - 매출이 얼마나 늘어야 손익분기인가?
        
    - 어느 요일·시간대가 병목인가?
        
- → **시뮬레이션이 불가능**
    

## ④ 마케팅·수가·재고가 연결되어 있지 않음

- 어떤 시술이:
    
    - 잘 팔리고
        
    - 시간이 적게 들고
        
    - 재고 부담이 낮은지
        
- → **가성비 판단 불가**
    

이건 “마케팅 문제”도, “직원 문제”도 아닙니다.  
**운영 데이터를 구조화하지 않은 문제**입니다.

---

# 2. 만들어야 할 소프트웨어의 정체

### 이름부터 명확히 정의하는 게 중요합니다

> **병원 운영 대시보드 (Clinic Operations OS)**

### 전자차트와의 관계

- ❌ 대체 아님
    
- ⭕ 전자차트 _밖에서_ 데이터를 요약·판단하는 시스템
    

---

# 3. 반드시 만들어야 할 핵심 모듈 5개

아래는 “있으면 좋은 기능”이 아니라  
**이 병원 상황에서 반드시 필요한 최소 구성**입니다.

---

## ① 실시간 운영 현황 대시보드 (최우선)

### 기능

- 오늘 기준
    
    - 대기 환자 수
        
    - 시술 중 / 마취 대기 / 사진실 / 관리베드 상태
        
- 시술별 예상 소요 시간
    
- 지연 발생 시 색상 경고
    

### 왜 필요한가

- “오늘 왜 이렇게 밀리지?”를 **감으로 판단하지 않게 하기 위해**
    
- 바쁜 날의 분노·사고 대부분은 **현황 파악 실패**에서 발생
    

### 입력 방식

- 직원이 클릭 1~2번
    
- 예:
    
    - `마취 시작`
        
    - `시술 시작`
        
    - `시술 종료`
        

---

## ② 시술·시간·매출 연결 모듈

### 기능

- 시술별
    
    - 평균 소요 시간
        
    - 평균 매출
        
    - 시간당 매출(핵심)
        

### 결과

- “이 병원에서 가장 돈 되는 시술”
    
- “시간은 오래 걸리는데 효율 낮은 시술”
    
- → **수가 조정·의사 배치 근거 확보**
    

### 중요 포인트

- 정밀할 필요 없음
    
- **±5분 오차 허용**
    
- 완벽함보다 “경향”이 목적
    

---

## ③ 재고 자동 차감 + 경고 시스템

### 기능

- 시술 선택 → 재고 자동 차감
    
- 기준 이하 시:
    
    - 색상 경고
        
    - “주문 필요” 표시
        
- 월별 소모량 시각화
    

### 회의록 근거

- 현재:
    
    - 수기 → 엑셀 → 재확인
        
- 반복 노동 + 오류 + 원장 개입 과다
    

### 핵심

- 재고 관리는 **‘기록’이 아니라 ‘흐름’** 문제
    

---

## ④ 환자 안전·실수 방지 체크리스트 (의외로 가장 중요)

### 기능

환자 클릭 시 자동 팝업:

- 알러지
    
- 금기 시술
    
- 반드시 체크해야 할 항목
    
    - 정품 스티커
        
    - 주의사항 전달
        
    - 사후 영상/문자 발송
        

### 왜 중요한가

- 의료 사고의 80%는 **기술 부족이 아니라 체크 누락**
    
- “알았는데 못 했다”를 시스템으로 막아야 함
    

---

## ⑤ 경영 시뮬레이션 모듈 (원장 전용)

### 기능

- 입력:
    
    - 의사 수
        
    - 근무일
        
    - 평균 시술 시간
        
    - 평균 수가
        
- 출력:
    
    - 예상 최대 매출
        
    - 손익분기점
        
    - 병목 시간대
        

### 회의록 핵심 질문에 대한 직접적 답

- “의사 1명 더 뽑으면?”
    
- “수가를 낮추면 회전이 얼마나 늘어야 버티나?”
    

→ **이걸 숫자로 보여주는 도구**

---

# 4. “어떻게 만들 것인가” (현실적인 방법)

## ❌ 하지 말아야 할 방법

- SI 업체에 외주
    
- “병원 ERP” 구매
    
- 기능 많은 올인원 솔루션
    

→ **비싸고, 수정 불가, 결국 안 씀**

---

## ⭕ 추천 방법: 단계적 자체 구축

### 1단계 (1~2주)

**목표:** “보이게 만들기”

- Google Sheets / Notion DB / Supabase 중 하나
    
- 최소 컬럼:
    
    - 날짜
        
    - 시술명
        
    - 시작/종료
        
    - 사용 재고
        
- 간단한 대시보드 연결
    

👉 _이 단계만으로도 체감 변화 큼_

---

### 2단계 (1개월)

**목표:** “흐름 자동화”

- 클릭 기반 입력 UI
    
- 재고 자동 차감
    
- 시술 시간 평균 계산
    

기술 스택 예:

- Front: 웹 기반 (태블릿/PC 공용)
    
- Backend: Supabase / Firebase
    
- Dashboard: Metabase / Retool / 자체 제작
    

---

### 3단계 (선택)

**목표:** “의사결정 도구화”

- 시뮬레이션 기능
    
- 수가·인력 시나리오 비교
    
- 원장 전용 화면
    

---

# 5. 이 시스템의 본질 (중요)

이 소프트웨어는  
❌ 직원 감시 도구가 아닙니다.  
❌ 마케팅 도구도 아닙니다.

> **원장이 ‘덜 불안해지기 위한 도구’**입니다.

- 감이 아니라 **근거로 결정**
    
- 사람 늘리기 전에 **구조를 먼저 점검**
    
- 실수를 개인 문제가 아니라 **시스템 문제로 전환**
