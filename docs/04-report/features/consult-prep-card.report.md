## 1. 무엇을 만들었나

홈의 고민 카드 5종을 클릭하면 3단계 질문(고민 확인 → **자유 서술 필수** → 시기)을 받고, 결과 카드 4장을 보여준 뒤 문의로 잇는다.

| 카드 | 내용 | 출처 |
|---|---|---|
| 1 | 말씀하신 건 보통 이렇게 부릅니다 | 용어 사전(고정) + 되받기 1문장(생성) |
| 2 | 이 부위를 다루는 시술 | 규칙표(`displayOrder` 고정 순서) |
| 3 | 상담에서 물어보세요 | 질문 은행(고정), 정확히 3개 |
| 4 | 참고 — 소요시간·마취·회복·주의사항 | `TREATMENTS` |

**노린 것:** `consultation_requests` 68건 중 48건(71%)이 시술을 고르지 못하고 "빠른 상담"만 누르는 문제. 홈페이지 유입의 예약 전환은 29%로 지인소개(83%)의 3분의 1이었다.

### 규모

```
19 커밋 · 35+ 파일 · 테스트 194개 → 329개
```

지원 언어는 ko/en/ja/zh 4종. 나머지 7개 로케일은 진입점을 노출하지 않고 기존 시술 페이지 링크를 유지한다.

## 2. 설계의 핵심 — LLM은 고르기만 한다

이 기능에서 LLM이 하는 일은 **분류와 선택**뿐이다.

- 용어는 사전에서, 시술은 규칙표가 준 후보에서, 질문은 은행에서 **고른다.**
- 생성하는 것은 "손님 말 되받기" 한 문장뿐이고, 그마저 금지어 검사를 통과해야 화면에 오른다.
- 사전·규칙표·은행에 없는 id는 버린다. 고민 스코프를 벗어난 id도 버린다.
- **화면 순서는 LLM이 준 배열이 아니라 정렬된 규칙표를 순회해 만든다.** 점수 정렬이 들어오면 화면이 '목록'에서 '추천'으로 바뀌어 규제선을 넘는다. 신규 코드 전체에 `.sort(`는 `rules.ts` 한 곳뿐이고, `.sort()`를 지우면 실패하는 회귀 테스트가 걸려 있다.

### AI가 죽어도 화면이 나온다

7가지 실패 사유(`no_api_key` / `invalid_json` / `not_an_object` / `empty_payload` / `timeout` / `fetch_error` / `http_{n}`)가 전부 규칙표 폴백으로 수렴한다. `classify`에 throw 경로가 없다.

폴백이 일어나면 사유 코드만 `console.warn`으로 남는다. **손님 입력은 로그·URL·애널리틱스 어디에도 남지 않는다** — POST 바디로만 가고, GA4에는 길이(숫자)만 간다.

### 검수를 빌드가 강제한다

규칙표는 원장·실장이 엑셀로 편집하는 CSV 3종(`liv-clinic/data/`)이고, `prebuild`가 검증해 TS 상수로 굽는다. 다음은 **빌드 실패**다:

- `reviewed_by`가 `원장`·`실장`·`원장,실장`이 아님
- `treatment_id`가 `TREATMENTS`에 없음 (`consultOnly` 제외)
- `answer_source`가 `TREATMENTS` 필드가 아님 — **답이 없는 질문은 만들 수 없다**

번역 누락은 경고만 낸다. 원장이 한국어부터 채우는 실제 순서를 막지 않기 위해서다.

## 3. 리뷰가 잡아낸 것 (기록)

태스크별 리뷰 9회 + 수정 라운드 5회 + 브랜치 전체 리뷰 1회. **테스트와 빌드가 통과한 뒤에 발견된 것들**만 남긴다 — 같은 함정을 다시 밟지 않기 위해서다.

| 무엇 | 어떻게 드러났나 |
|---|---|
| **공허한 정렬 테스트** | `.sort()`를 지워도 10개 테스트가 전부 통과. 규칙표 CSV가 이미 정렬돼 있어 배열을 자기 자신과 비교하는 방식이 아무것도 못 잡았다 |
| **거짓말하는 신뢰도 신호** | LLM이 `{}`·`[]`·`"문자열"`을 줘도 `lowConfidence:false`. 내용은 100% 폴백인데 "정상"으로 표기됐다 |
| **모델 계열 분기 부재** | 비-reasoning 모델을 env로 지정하면 400 → throw-free라 조용한 폴백. `translation.ts`가 같은 사고를 겪고 주석으로 경고해 둔 함정을 옆 파일에 다시 팠다 |
| **빈 껍데기 정적 페이지** | 빌드 성공, 로그에 "정적 생성" 표시. HTML을 열어보니 `BAILOUT_TO_CLIENT_SIDE_RENDERING` 마커와 로딩 스피너뿐이었다 |
| **한국어 전용 금지어 검사** | Task 1이 `lang` 없는 세계에서 한국어 목록을 만들었고, Task 4가 4개 언어 생성을 넣으면서 전제가 무너졌는데 아무도 Task 1로 돌아가지 않았다. en/ja/zh에서 의료광고 검사가 무력했다 |
| **URL로 새는 자유 서술** | 손님 고민 문장이 `/contact` 쿼리스트링에 200자까지 실렸다. 히스토리·액세스 로그·GA4에 남는 경로 |
| **`toning` 링크 누락** | 규칙표에 있는 시술이 링크 맵에 없어 카드 링크가 조용히 사라졌다. 지금은 규칙표의 모든 시술이 링크를 갖는지 테스트가 지킨다 |

## 4. 시연 전 결정이 필요한 것

### (1) "이대로 상담 문의하기" 버튼이 약속을 못 지킨다

결과 카드 하단 CTA가 4개 언어 모두 "이 내용이 넘어간다"고 말한다(`이대로 상담 문의하기` / `Send this as an inquiry` / `この内容で相談する` / `就以此内容咨询`). 실제로는 `/contact`가 쿼리를 읽지 않아 **빈 폼**이 뜬다. 손님은 방금 3단계에 걸쳐 입력한 것을 다시 적어야 한다.

시연에서 특히 아픈 이유는 **바로 그 지점이 이 기능이 해결하겠다고 선언한 문제**이기 때문이다. 관계자는 결과 카드가 아니라 마지막 화면을 기억한다.

| | 선택 | 비용 |
|---|---|---|
| 가 | CTA 문구를 약속하지 않는 말로 (`상담 문의하기`) | 몇 분 |
| 나 | 시연을 결과 카드에서 끊는다 | 0분. 단 버튼이 보이므로 눌린다 |
| 다 | `/contact` 프리필을 구현한다 | 2차 범위. 자유 서술은 URL이 아닌 경로로 넘겨야 한다 |

부수 효과: `procedure_tags` 저장이 없어 설계 §2의 성공 기준 1·2를 **측정할 수 없다.** GA4로 퍼널 진입까지만 보인다.

### (2) 3단계(시기)가 수집만 하고 버려진다

`timing`/`stay` 값이 API로 가지 않는다. 1차 범위 결정이었지만, 손님이 "자녀 결혼식"을 고르고 결과에 아무 반영이 없다. **살릴지(일정 역산 착수) 뺄지** 정해야 한다. 접근성 항목 하나(프리셋 버튼 `aria-pressed`)가 이 결정에 매달려 있다 — 죽은 컨트롤에 접근성을 붙이는 건 순서가 틀렸다.

### (3) `texture` 고민의 시술 목록이 홈 카드와 어긋난다

| 고민 | 홈 카드 tags | 준비 카드 결과 |
|---|---|---|
| sagging | 압토스 · 실리프팅 | 압토스 · 실리프팅 · 울쎄라 |
| elasticity | 울쎄라 · 써마지 · 복합 리프팅 | 울쎄라 · 써마지 · 덴서티 |
| fundamental | 안면거상 상담 | (상담) · 압토스 · 울쎄라 |
| underEye | 지방재배치 상담 | (상담) · 필러 · 스킨부스터 |
| **texture** | **포텐자 · 리쥬란 · 쥬베룩** | **스킨부스터 · 레이저토닝 · 스킨케어** |

클릭 한 번 사이로 겹치는 것이 0이다. **CSV 한 줄로는 못 고친다** — `potenza`/`rejuran`/`juvelook`은 `TREATMENTS`에 없어 생성기가 그 행을 거부한다. 홈 카드 문구를 바꾸거나 `TREATMENTS`에 항목을 추가해야 한다.

관련: `레이저 토닝`은 전용 페이지가 없어 `/laser/skintone`으로 보내고 있다(코드 주석 있음, 운영 확인 대기).

## 5. 다음 차수로 미룬 것

- **`/contact` 프리필 + `procedure_tags` 저장** — 성공 기준 측정에 필요
- **`adGuard` 차단 관측** — 지금은 차단이 일어나도 아무 기록이 없다. 히트 라벨 카운터 권장(손님 입력은 절대 로그 금지). 영어 `only`·`certain` 등 오탐이 남아 있는데 빈도를 알 방법이 없다
- **접근성** — 프리셋 버튼 `aria-pressed`, 단계 전환 시 포커스 이동
- **`.env.example`** — `OPENAI_CONSULT_PREP_MODEL` · `CONSULT_PREP_TIMEOUT_MS` · `CONSULT_PREP_REASONING_EFFORT` 미기재. 형제 변수는 이미 문서화돼 있어 일관성이 깨진 상태
- **`CONSULT_PREP_TIMEOUT_MS=""`** → `Number('')=0` → 즉시 abort → LLM 100% 무력화(조용함). `translation.ts`도 같은 패턴
- **카드 4 값의 한국어 노출** — 소요시간·마취·회복이 외국어 화면에서도 한국어다. **이 브랜치가 만든 문제가 아니라 사이트의 기존 상태**(기존 시술 상세 페이지도 동일). 별건
- **죽은 코드** — `isKnownTerm`/`isKnownQuestion`은 고민 스코프 검사로 대체돼 테스트만 살려두고 있다

## 6. 이 브랜치보다 큰 문제 (별도 티켓)

**248개 → 329개로 늘린 테스트를 돌리는 자동 파이프라인이 없다.** `.github/workflows/`가 없고 `netlify.toml`의 빌드 명령에도 테스트 호출이 없다. `prebuild`는 CSV 검증과 `verify:i18n`만 돈다.

이 브랜치가 심어둔 회귀 방지 장치들(정렬 테스트, 링크 커버리지 테스트, 금지어 테스트)의 가치가 전부 거기에 달려 있다. `npm run test:rules`는 어떤 기본 명령으로도 실행되지 않는다 — 손으로 쳐야만 돈다.
