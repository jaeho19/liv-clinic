## 0. 한눈에 보기 (비개발자용)

방 안의 `LIV 알림`에서 회색 작은 글씨 설명을 뺀다. 알림마다 핵심 한 줄만 남는다. 손님 글, 직원 답글, `번역본 · 복사용` 글은 바뀌지 않는다.

| 알림 | 지금 | 바뀐 뒤 |
|------|------|---------|
| 새 문의 (회색) | 큰 줄 + 설명 두 줄(사용법, 접수 안내가 나갔음) | `새 문의 · 📥 10/02(금) 14:06 KST · 참조코드 #CB55BC91` 한 줄 |
| 이벤트 링크 (회색) | `🎁 가격 문의로 보여 손님에게 이벤트 링크를 자동으로 보냈습니다. 가격은 직접 답해 주세요.` + 링크 | `🎁 이벤트 링크를 자동으로 보냈습니다` + 링크 |
| 연락처 남김 (초록) | 큰 줄 + 설명 세 줄 | `📱 손님이 연락처를 남겼습니다 — 이메일: …` 한 줄 |
| 병원 연락 단추 누름 (초록) | 큰 줄 + 설명 한 줄 | 큰 줄만 |
| 12분 재촉 (빨강) | `⏰ 12분째 답이 없습니다.` + "담당 @… 님이 응답하지 않아 전원에게 알립니다." | `⏰ 12분째 답이 없습니다.` 한 줄 |
| 5분·30분 재촉, 완료했던 손님이 다시 말을 걸었음 | 이미 한 줄 | 그대로 |
| 답글 전달 실패 (빨강) | 큰 줄 + 사유 | **그대로** — 사유를 알아야 다시 보낼 수 있다 |
| 시작 화면에서 이메일을 넣은 손님 | 새 문의 알림의 설명 셋째 줄("이메일을 남긴 손님입니다 — …") | 새 문의 알림 바로 아래 **초록 막대 한 줄** `📱 손님이 연락처를 남겼습니다 — 이메일: …` |

비용 0원. Slack 앱 권한·환경변수·DB 변경 없음.

## 2. 설계

### 2.1 규칙

손님 방의 `LIV 알림`은 **큰 줄 하나만** 올린다(색 막대 안의 `section` 블록 하나, `context` 블록 없음). 예외는 답글 전달 실패 알림 하나 — 사유를 `context` 한 줄로 남긴다.

### 2.2 알림별 문구

번호는 `2026-10-01-slack-room-look-design.md` §3.4 표의 번호다.

| # | 알림 | 색 | 큰 줄 | 설명 줄 |
|---|------|----|-------|---------|
| 2 | 새 문의 | 회색 | `*새 문의* · 📥 {접수 시각} · 참조코드 `#{코드}`` (지금과 같다) | 없음 |
| 2-1 | 시작 화면에서 이메일을 넣은 손님 | 초록 | `📱 *손님이 연락처를 남겼습니다* — 이메일: {주소}` — 2번과 **같은 글**의 둘째 막대 | 없음 |
| 4 | 다시 말을 걸었음 | 회색 | `🔔 *완료했던 문의에 손님이 다시 말을 걸었습니다*` (지금과 같다) | 없음 |
| 8 | 연락처 남김 | 초록 | `📱 *손님이 연락처를 남겼습니다* — {채널}: {연락처}` (지금과 같다) | 없음 |
| 9 | 병원 연락 단추 누름 | 초록 | `📲 손님이 … 확인해 주세요.` (지금과 같다) | 없음 |
| 10 | 이벤트 링크 | 회색 | `🎁 이벤트 링크를 자동으로 보냈습니다` + 다음 줄에 링크 | 없음 |
| 11 | 5분·12분 재촉 | 빨강 | `⏰ *{N}분째 답이 없습니다.*` (지금과 같다). 멘션은 지금처럼 최상위 `text` | 없음 |
| 12 | 30분 재촉 | 빨강 | `🚨 *{N}분째 미응답입니다.*` (지금과 같다) | 없음 |
| 13 | 답글 전달 실패 | 빨강 | `⚠️ *방금 답글이 손님에게 전달되지 않았습니다*` (지금과 같다) | `사유: …` (지금과 같다) |

### 2.3 시작 화면에서 이메일을 넣은 손님 (2-1)

- 조건은 지금의 꼬리말과 같다: 세션에 이메일이 있고, 이 글에서 방금 저장된 것이 아니고(그때는 8번 알림이 뒤따른다), `CHAT_FOLLOWUP`이 켜져 있을 때.
- 새 문의 알림 글 하나에 막대를 두 개 단다(`attachments` 두 요소): 회색 "새 문의" + 초록 "연락처". 게시 횟수는 늘지 않는다.
- 큰 줄은 8번 알림과 같은 문장이다 — 연락처는 언제나 같은 초록 한 줄로 보인다. 주소의 Slack 마크업은 지금처럼 이스케이프한다.
- 방 주제에는 지금처럼 이메일이 들어 있다.

### 2.4 그대로 두는 것

| 곳 | 이유 |
|----|------|
| 손님 글, 직원 답 사본, `번역본 · 복사용` | 원장님이 남기라고 한 내용 그 자체다 |
| **글자만 문구(`plainText`)** — `SLACK_ROOM_LOOK=off`이거나 Slack이 꾸민 글을 거부했을 때 대신 올라가는 문구 | 비상용이다. 지금까지 운영하던 문구를 그대로 두는 것이 안전하다. 긴급 정지 중에는 예전의 긴 문구가 보인다 |
| `#해외문의` 피드 줄, 하루 두 번 요약, 스레드 방식 세션의 글 | 이번 요청의 대상이 아니다 |
| 방 이름, 이름표, 막대 색, `postStyled`의 재게시 규칙, 멘션 위치 | 변경 없음 |

### 2.5 코드

`slackText.ts`(문구):
- `contactNoticeHeadline(channelLabel, handle): string` 신설 — 8번과 2-1이 같이 쓴다. `contactNoticeParts`가 이것을 쓴다.
- `EVENT_HINT_SHORT = '이벤트 링크를 자동으로 보냈습니다'` 신설 — 방의 10번 알림. 글자만 문구는 `EVENT_HINT_SENTENCE` 그대로.
- `roomFirstNoticeParts` → `roomFirstNoticeHeadline(args: { receivedAt, sessionId }): string`, `escalationNoticeParts` → `escalationNoticeHeadline(args: { level, minutes }): string`. 설명 줄을 만들던 부분과 `bareNote`를 지운다(쓰는 곳이 없어진다).
- `contactNoticeParts`·`messengerClickParts`의 설명 줄은 남긴다 — 글자만 문구(`buildContactText`·`buildMessengerClickText`)가 쓴다. `deliveryFailureParts`도 그대로.
- `build…Text` 함수들이 내는 글자는 하나도 바뀌지 않는다.

`slackLook.ts`(모양):
- 내부 `notice(kind, headline, plainText, opts?)` — 큰 줄만 받는다. `opts.notes`는 전달 실패만 넘긴다.
- `styledRoomFirstNotice(args: RoomFirstNoticeArgs & { contactEmail?: string | null })` — `contactEmail`이 있으면 초록 막대를 하나 더 단다.
- `styledEventHint`는 `EVENT_HINT_SHORT`를 쓴다. 나머지 `styled…` 함수의 인자와 `plainText`는 그대로.
- `bar()`는 그대로(설명 줄이 있으면 `context` 블록을 만든다 — 전달 실패가 쓴다).

`slackRelay.ts`: `postInRoom`이 첫 알림을 만들 때 `contactEmail`을 넘긴다(꼬리말 조건이 참일 때의 `session.visitor_email`). 그 밖은 변경 없음. `escalationRunner.ts`는 변경 없음(`styledEscalation`의 인자가 그대로다).

## 4. 롤아웃

1. 구현 → 검증 게이트.
2. **승인** master 푸시(= Netlify 배포). 배포 뒤 올라오는 알림부터 한 줄이 된다. 이미 올라온 글은 바뀌지 않는다.
3. 확인: 다음 문의가 들어온 방을 원장님이 본다. 큰 줄만 있는 막대는 이미 운영에서 보인 꼴이다(이벤트 링크 알림 — 2026-10-02 시험 문의의 캡처). 새로운 꼴은 "한 글에 막대 두 개"(2-1) 하나 — Slack이 거부하면 `postStyled`가 글자만 문구로 다시 올린다.
4. 직원 안내문(§5)을 `#해외문의`에 올린다.

되돌리기: 커밋 되돌리기(승인 필요). 긴급 정지 `SLACK_ROOM_LOOK=off`는 예전의 긴 글자 문구로 돌아간다.

## 6. 하지 않는 것

- 손님 글의 이름표에 언어 이름 적기, 직원 답글의 번역문을 항상 올리기(원장님이 고르지 않았다).
- 글자만 문구(비상용)·`#해외문의` 피드·스레드 방식의 문구 줄이기.
- 병원 연락 단추 알림의 큰 줄 문장 고치기(코드와 확인할 곳이 들어 있는 한 문장이다).
- 이미 올라온 글 고치기.
