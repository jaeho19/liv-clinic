# Slack 환자별 채널 — 원장님이 직접 하실 일 (설정 안내)

> 작성: 2026-09-03 · 대상: 원장님(Slack 워크스페이스 관리자 겸 Netlify 관리자)
> 설계: `2026-09-03-slack-patient-rooms-design.md` · 구현 계획: `../plans/2026-09-03-slack-patient-rooms.md`
> 코드는 Claude가 만듭니다. 이 문서는 **Slack과 Netlify 화면에서 사람이 눌러야 하는 것만** 순서대로 적었습니다. 총 20~30분 걸립니다.

---

## 0. 순서 한눈에 보기

| 순서 | 어디서 | 무엇을 | 언제 |
|:---:|--------|--------|------|
| A | api.slack.com | 봇 권한 2개 추가 | **지금 해도 됨** (현행 코드에 영향 없음) |
| B | api.slack.com | 이벤트 2개 추가 | A와 같이 |
| C | api.slack.com | 앱 재설치 + 토큰 확인 | A·B 직후 |
| D | Slack 앱 | 워크스페이스 설정 1개 확인 | 아무 때나 |
| E | Slack 앱 | 직원·원장님 멤버 ID 확인 | 아무 때나 |
| F | Netlify | 환경변수 4개 넣기 (`SLACK_STAFF`는 아직 비움) | 코드 배포 **전** |
| G | Netlify | `SLACK_STAFF`·`SLACK_OBSERVERS` 채우고 재배포 | 코드 배포 후 스모크가 끝난 뒤 |
| H | Slack 앱 | 배포 첫날 확인 4가지 | G 직후 |
| I | 직원들 | 사용법 공유 (아래 §9를 그대로 전달) | G 직후 |

## 1. A — 봇 권한(스코프) 2개 추가

1. 브라우저에서 <https://api.slack.com/apps> 에 접속해 워크스페이스 관리자 계정으로 로그인합니다.
2. 목록에서 **우리 상담봇 앱**(현재 `#해외문의`에 글을 올리는 앱)을 클릭합니다.
3. 왼쪽 메뉴 **OAuth & Permissions** 를 클릭합니다.
4. 아래로 내려 **Scopes** 구역의 **Bot Token Scopes** 에서 **Add an OAuth Scope** 버튼을 누릅니다.
5. `groups:write` 를 입력해 선택합니다. 한 번 더 **Add an OAuth Scope** 를 눌러 `groups:read` 를 추가합니다.
6. 목록에 다음 네 개가 보이면 됩니다: `chat:write`, `groups:history`, `groups:write`, `groups:read`.

> 각각의 뜻 — `groups:write`: 비공개 채널을 만들고, 직원을 초대하고, 보관/해제한다. `groups:read`: 직원이 채널을 직접 보관했을 때 그 사실을 받아본다.

## 2. B — 이벤트 2개 추가

1. 같은 앱 화면 왼쪽 메뉴 **Event Subscriptions** 를 클릭합니다. (**Enable Events** 가 이미 켜져 있고 Request URL이 등록돼 있을 겁니다. 건드리지 않습니다.)
2. **Subscribe to bot events** 구역을 펼치고 **Add Bot User Event** 를 누릅니다.
3. `group_archive` 를 추가하고, 한 번 더 눌러 `group_unarchive` 를 추가합니다.
4. 목록에 `message.groups`, `group_archive`, `group_unarchive` 세 개가 보이면 화면 **오른쪽 아래 Save Changes** 를 누릅니다. (이 버튼을 안 누르면 저장되지 않습니다.)

## 3. C — 앱 재설치와 토큰 확인

1. 권한을 바꾸면 화면 **위쪽에 노란 띠**가 뜹니다. 띠 안의 **reinstall your app** 링크를 누릅니다. (띠가 없으면 왼쪽 메뉴 **Install App** → **Reinstall to Workspace**.)
2. 권한 확인 화면에서 **허용(Allow)** 을 누릅니다.
3. 다시 **OAuth & Permissions** 로 가서 맨 위 **Bot User OAuth Token** (`xoxb-` 로 시작) 값을 봅니다.
4. Netlify에 저장된 `SLACK_BOT_TOKEN`(§6 참고)과 **같은지 비교**합니다. 보통 같지만, 다르면 Netlify 값을 이 새 값으로 바꾸고 재배포합니다.

## 4. D — 워크스페이스 설정 1개 확인

봇이 비공개 채널을 만들 수 있어야 합니다. 이게 막혀 있으면 코드가 자동으로 지금 방식(스레드)으로 되돌아가므로 위험하지는 않지만, 방이 안 생깁니다.

1. Slack 앱(데스크톱) 왼쪽 위 **워크스페이스 이름**을 클릭합니다.
2. **도구 및 설정 → 워크스페이스 설정** 을 엽니다. (브라우저가 열립니다.)
3. 위쪽 **권한** 탭 → **채널 관리** 항목의 **펼치기** 를 누릅니다.
4. **"비공개 채널을 만들 수 있는 사람"** 이 **모든 멤버** 인지 확인합니다. 아니면 모든 멤버로 바꾸고 저장합니다.

## 5. E — 멤버 ID 확인

봇이 방에 초대하고 멘션할 사람을 ID로 알려줘야 합니다. 이름이 아니라 **`U`로 시작하는 ID**입니다.

이미 확보된 답변 직원 3명 (09-01 계획서 §13.1):

| 이름 | 멤버 ID |
|------|---------|
| 이정현 | `U0BMYAJKMJQ` |
| 정소월 | `U0BMYAMNASG` |
| 방애금 | `U0BMUKXLL3C` |

**원장님 본인 ID** 는 이렇게 봅니다: Slack에서 본인 프로필 사진 클릭 → **프로필 보기** → 이름 옆 **⋮(더보기)** → **멤버 ID 복사**. 새 직원이 오면 같은 방법으로 ID를 얻어 §6의 `SLACK_STAFF`에 한 명 더 붙입니다.

## 6. F — Netlify 환경변수 (코드 배포 전)

1. <https://app.netlify.com> → 우리 사이트 → **Site configuration → Environment variables** → **Add a variable**.
2. 아래 값을 하나씩 넣습니다. 이름은 대문자 그대로, 값 앞뒤에 공백이 없어야 합니다.

| 이름 | 값 | 설명 |
|------|-----|------|
| `SLACK_STAFF` | **(지금은 비워 둠 — §7에서 채움)** | 답변 직원 명단. 비어 있으면 방을 만들지 않고 지금 방식 그대로 동작 |
| `SLACK_OBSERVERS` | **(지금은 비워 둠 — §7에서 채움)** | 지켜보기만 하는 계정(원장님) |
| `SLACK_ROOM_PREFIX` | `chat` | 채널 이름 앞머리. 첫날 시험 뒤 `문의`로 바꿔 볼 수 있음 |
| `CHAT_OPS_SECRET` | 무작위 문자열 40자 (아래 만들기) | 3분마다 도는 미응답 확인 작업의 비밀번호 |
| `CHAT_ESCALATION_MINUTES` | `5,12,30` | 미응답 알림 간격(분). 나중에 이 값만 바꾸면 됨 |

무작위 문자열 만들기 — PowerShell을 열고 아래를 붙여 넣으면 40자가 나옵니다. 그대로 복사해 `CHAT_OPS_SECRET` 값으로 넣습니다.

```powershell
-join ((48..57)+(65..90)+(97..122) | Get-Random -Count 40 | ForEach-Object {[char]$_})
```

3. 기존 값 `SLACK_BOT_TOKEN`, `SLACK_SIGNING_SECRET`, `SLACK_CHANNEL_ID` 는 **그대로 둡니다.** `SLACK_CHANNEL_ID`는 계속 `#해외문의`이며, 이 채널은 앞으로 "새 문의 / 완료 / 다시 열림 / 미응답" 한 줄 알림이 흐르는 피드가 됩니다.

> ⚠️ Netlify는 환경변수를 바꿔도 **다음 배포부터** 반영합니다. 값을 넣거나 고쳤으면 **Deploys → Trigger deploy → Deploy site** 를 한 번 누르세요. 무료 플랜이라 배포 비용은 없습니다.

## 7. G — 직원 명단 채우고 재배포 (코드 배포 후)

Claude가 코드를 배포하고 "스모크 정상"이라고 알려 드리면:

1. Netlify 환경변수에서 `SLACK_STAFF` 값을 넣습니다. 형식은 `ID:이름` 을 쉼표로 이어 붙입니다. 이름은 관리자 화면에 "Slack · 이정현"처럼 표시되는 데 쓰입니다.
   ```
   U0BMYAJKMJQ:이정현,U0BMYAMNASG:정소월,U0BMUKXLL3C:방애금
   ```
2. `SLACK_OBSERVERS` 에 원장님 ID를 넣습니다. 예: `U0XXXXXXXXX:이재호`. 이 계정은 모든 방에 초대되어 **보기만** 하고, 멘션도 받지 않고 담당자도 되지 않습니다.
3. **Deploys → Trigger deploy → Deploy site** 로 재배포합니다.
4. 재배포가 끝나면(2~4분) 홈페이지 외국어 페이지에서 채팅으로 문의를 하나 보내 봅니다. Slack 사이드바에 `chat-이름-코드` 방이 생기고 직원 3명이 멘션되면 성공입니다.

## 8. H — 배포 첫날 확인 4가지

| 확인 | 방법 | 안 되면 |
|------|------|---------|
| 한글 채널 이름 | `SLACK_ROOM_PREFIX`를 `문의`로 바꾸고 재배포 → 새 문의 1건 → 방 이름이 `문의-…`인지 | 자동으로 `chat-…`로 만들어집니다. 그대로 두면 됩니다 |
| 방 되살리기 | 방을 완료(보관)한 뒤 그 손님 채팅창에서 메시지를 하나 더 보냄 → 방이 다시 나타나고 🔔 표시가 붙는지 | Netlify **Logs → Functions** 에서 `[slack relay]` 로 시작하는 줄을 Claude에게 보내 주세요 |
| 휴대폰 알림 | 직원 3명의 휴대폰에 첫 문의 멘션 푸시가 오는지 | Slack 앱 알림 설정에서 "멘션" 알림이 켜져 있는지 확인 |
| 내부 메모 | 방 안에서 메시지에 마우스를 올려 **스레드로 답글** 을 남김 → 손님 채팅창에 **안 나타나는지** | 나타난다면 즉시 Claude에게 알려 주세요 |

## 9. I — 직원에게 공유할 사용법 (이대로 복사해서 보내셔도 됩니다)

```
[해외 문의 채팅 — 새 방식 안내]

1. 손님이 홈페이지에서 문의하면 Slack에 손님별 방(#chat-이름-코드)이 생기고 전원이 멘션됩니다.
   손님에게는 "잠시만 기다려 주세요, 곧 답변드리겠습니다" 안내가 자동으로 먼저 나가 있습니다.
2. 그 방에 한국어로 답을 쓰면 손님 언어로 번역되어 바로 전달됩니다. 먼저 답한 사람이 담당자가 됩니다.
3. 손님이 이어서 말하면 담당자만 멘션됩니다. 5분 안에 답이 없으면 담당자에게 한 번 더,
   12분이면 전원에게, 30분이면 🚨와 함께 전원에게 알림이 갑니다. 답을 쓰면 알림이 멈춥니다.
4. 직원끼리 상의할 내용은 메시지에 마우스를 올려 "스레드에서 답글"로 남기세요. 스레드는 손님에게 가지 않습니다.
   (방 본문에 쓴 것은 전부 손님에게 갑니다.)
5. 상담이 끝나면 방 이름 클릭 → 설정 → "채널 보관"을 누르세요. 방이 목록에서 사라집니다.
   관리자 화면(/admin/chat)의 "완료 처리" 버튼을 눌러도 됩니다. 손님에게는 아무 메시지도 가지 않습니다.
6. 보관한 손님이 다시 말을 걸면 방이 저절로 되살아나고 🔔 표시와 함께 담당자가 멘션됩니다.
7. #해외문의 채널은 이제 "새 문의 / 완료 / 다시 열림 / 미응답" 한 줄 기록만 흐릅니다. 음소거해도 방 멘션은 옵니다.
8. 대화 기록 전체는 관리자 화면에 영구 보관됩니다. Slack 무료 플랜은 90일 뒤 지난 메시지를 가리지만 기록은 사라지지 않습니다.
```

## 10. 문제가 생기면

| 증상 | 원인 후보 | 할 일 |
|------|-----------|-------|
| 방이 안 생기고 예전처럼 `#해외문의` 스레드로 온다 | `SLACK_STAFF` 비어 있음 / 재배포 안 함 / 권한 미추가 / §4 설정이 막힘 | Netlify **Logs → Functions** 에서 `[slack rooms] create failed:` 뒤의 단어를 확인 — `missing_scope`면 §1·§3, `restricted_action`이면 §4, 아무 로그도 없으면 §6·§7 재확인 |
| 방은 생겼는데 직원에게 안 보인다 | 초대 실패 | 같은 로그에서 `invite failed:` 확인. 코드가 그 방을 보관하고 스레드로 되돌립니다. ID 오타를 의심하세요 |
| 멘션이 회색 글자 `<@U…>`로 보인다 | ID가 틀림 | §5에서 ID를 다시 복사해 `SLACK_STAFF` 수정 → 재배포 |
| 미응답 알림이 안 온다 | `CHAT_OPS_SECRET` 미설정 / 영업시간 외 | Netlify **Functions → chat-ops** 에서 최근 실행 로그 확인. 영업시간(평일 10~19, 토 10~16) 밖에는 원래 안 옵니다 |
| 자동 안내가 손님에게 안 보인다 | 같은 대기 구간의 두 번째 메시지 | 정상입니다. 직원이 답한 뒤 손님이 다시 쓰면 다시 나갑니다 |

되돌리기: 언제든 `SLACK_STAFF` 값을 비우고 재배포하면 **그 순간부터 새 문의는 지금 방식(스레드)** 으로 돌아갑니다. 이미 만들어진 방은 그대로 남아 계속 동작합니다.
