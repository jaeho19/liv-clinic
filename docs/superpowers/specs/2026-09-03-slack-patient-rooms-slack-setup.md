## 1. A — 봇 권한(스코프) 3개 추가

1. 브라우저에서 <https://api.slack.com/apps> 에 접속해 워크스페이스 관리자 계정으로 로그인합니다.
2. 목록에서 **우리 상담봇 앱**(현재 `#해외문의`에 글을 올리는 앱)을 클릭합니다.
3. 왼쪽 메뉴 **OAuth & Permissions** 를 클릭합니다.
4. 아래로 내려 **Scopes** 구역의 **Bot Token Scopes** 에서 **Add an OAuth Scope** 버튼을 누릅니다.
5. `groups:write` 를 입력해 선택합니다. 한 번 더 **Add an OAuth Scope** 를 눌러 `groups:read` 를 추가합니다. 한 번 더 **Add an OAuth Scope** 를 눌러 `users:read` 를 추가합니다.
6. 목록에 다음 다섯 개가 보이면 됩니다: `chat:write`, `groups:history`, `groups:write`, `groups:read`, `users:read`.

> 각각의 뜻 — `groups:write`: 비공개 채널을 만들고, 직원을 초대하고, 보관/해제한다. `groups:read`: 직원이 채널을 직접 보관했을 때 그 사실을 받아보고, `#해외문의` 채널의 사람 멤버 목록을 읽어 답변 직원 명단을 만든다. `groups:history`: `#해외문의`의 피드 줄(스레드 답장이 달린 부모 메시지)을 읽어 손님 방으로 연결한다. `users:read`: 직원 이름을 Slack 프로필에서 읽어 관리자 화면·방에 표시한다.

> 2026-09-10 추가. 이미 설치된 앱이면 스코프 추가 후 **§3 재설치**를 한 번 더 한다. 토큰 값은 바뀌지 않는다.

> 2026-10-01 추가: `chat:write.customize` — 손님 방 안에서 글마다 보낸 사람 이름과 아이콘을 바꾼다(손님 글은 `이름 손님` + 국기, 알림은 `LIV 알림`, 번역본은 `번역본 · 복사용`). 같은 방법으로 추가하고 재설치한다. **2026-10-01에 추가·재설치를 마쳤고 토큰은 바뀌지 않았다.** 목록은 이제 여섯 개다: `chat:write`, `chat:write.customize`, `groups:history`, `groups:write`, `groups:read`, `users:read`. 설계: `2026-10-01-slack-room-look-design.md`.

## 2. B — 이벤트 2개 추가

1. 같은 앱 화면 왼쪽 메뉴 **Event Subscriptions** 를 클릭합니다. (**Enable Events** 가 이미 켜져 있고 Request URL이 등록돼 있을 겁니다. 건드리지 않습니다.)
2. **Subscribe to bot events** 구역을 펼치고 **Add Bot User Event** 를 누릅니다.
3. `group_archive` 를 추가하고, 한 번 더 눌러 `group_unarchive` 를 추가합니다.
4. 목록에 `message.groups`, `group_archive`, `group_unarchive` 세 개가 보이면 화면 **오른쪽 아래 Save Changes** 를 누릅니다. (이 버튼을 안 누르면 저장되지 않습니다.)

## 3. C — 앱 재설치와 토큰 확인

1. 권한을 바꾸면 화면 **위쪽에 노란 띠**가 뜹니다. 띠 안의 **reinstall your app** 링크를 누릅니다. (띠가 없으면 왼쪽 메뉴 **Install App** → **Reinstall to Workspace**.)
2. 권한 확인 화면에서 **허용(Allow)** 을 누릅니다.
3. 다시 **OAuth & Permissions** 로 가서 맨 위 **Bot User OAuth Token** (`xoxb-` 로 시작) 값을 봅니다.
4. Netlify에 저장된 `SLACK_BOT_TOKEN`(§6 참고)과 **같은지 비교**합니다. 보통 같지만, 다르면 Netlify 값을 이 새 값으로 바꾸고 재배포합니다.

## 4. D — 워크스페이스 설정 1개 확인

봇이 비공개 채널을 만들 수 있어야 합니다. 이게 막혀 있으면 코드가 자동으로 지금 방식(스레드)으로 되돌아가므로 위험하지는 않지만, 방이 안 생깁니다.

1. Slack 앱(데스크톱) 왼쪽 위 **워크스페이스 이름**을 클릭합니다.
2. **도구 및 설정 → 워크스페이스 설정** 을 엽니다. (브라우저가 열립니다.)
3. 위쪽 **권한** 탭 → **채널 관리** 항목의 **펼치기** 를 누릅니다.
4. **"비공개 채널을 만들 수 있는 사람"** 이 **모든 멤버** 인지 확인합니다. 아니면 모든 멤버로 바꾸고 저장합니다.

## 5. E — 직원 추가·제외 (채널 멤버로만)

2026-09-10부터 답변 직원 명단은 **`#해외문의` 채널의 사람 멤버**로 자동 정해집니다. 멤버 ID를 찾거나 Netlify에 적을 일이 없습니다.

- **새 직원**: `#해외문의` 채널에서 "채널에 사람 추가"로 초대합니다. 다음 손님 문의부터 자동으로 방에 초대되고 멘션됩니다.
- **퇴사자**: `#해외문의`에서 내보냅니다(또는 Slack 계정 비활성화). 이후 새 방에 초대되지 않습니다.
- **원장님(관찰자)**: 채널에 있어도 `SLACK_OBSERVERS`에 적혀 있으면 멘션·담당에서 빠집니다(§6).
- 이미 만들어진 손님 방에는 소급되지 않습니다. 필요하면 그 방에서 직접 초대하세요.

## 6. F — Netlify 환경변수 (코드 배포 전)

1. <https://app.netlify.com> → 우리 사이트 → **Site configuration → Environment variables** → **Add a variable**.
2. 아래 값을 하나씩 넣습니다. 이름은 대문자 그대로, 값 앞뒤에 공백이 없어야 합니다.

| 이름 | 값 | 설명 |
|------|-----|------|
| `SLACK_OBSERVERS` | `U0BMNA7292P:이재호` | 지켜보기만 하는 계정(원장님). 방에 초대만 되고 멘션·담당 대상이 아니다 |
| `SLACK_ROOMS` | 비워 둠 | `off`로 두면 긴급 정지(방 생성·멘션·확대 알림 중지, 스레드 방식) |
| `SLACK_ROOM_LOOK` | 비워 둠 | `off`로 두면 손님 방 안의 글을 예전 모양(글자만)으로 올린다 — 이름표·색 막대에 문제가 생겼을 때의 긴급 정지. 방 이름은 그대로다 (2026-10-01 추가) |
| `CHAT_OPS_SECRET` | 무작위 문자열 40자 (아래 만들기) | 3분마다 도는 운영 작업("오늘 연락할 손님" 요약 등)의 비밀번호. 지우면 요약도 멈춘다 |
| `CHAT_ESCALATION` | 비워 둠 | 재촉 알림 스위치. **2026-10-02부터 비어 있으면 꺼짐**이다. `on`으로 두고 재배포하면 방의 5·12·30분 알림과 `#해외문의` 🚨 줄이 다시 켜진다 — 켜기 전에 아래 "재촉 알림을 다시 켤 때"를 먼저 할 것 |
| `CHAT_ESCALATION_MINUTES` | `5,12,30` | 재촉 알림 간격(분). `CHAT_ESCALATION=on`일 때만 쓰인다 |
| `CHAT_AI` | 비워 둠 | **AI 1차 응대 스위치.** 비어 있으면 꺼짐(지금 방식). `test` = 손님 이름이 `ai-test`로 시작하는 문의에만 AI가 답한다(시험용). `on` = 모든 문의. **긴급 정지: 값을 지우거나 `off`로 바꾸고 재배포(약 2분)** (2026-10-02 추가) |
| `OPENAI_CHAT_AI_MODEL` | 비워 둠 | 답을 쓰는 모델. 비어 있으면 `gpt-6-sol` |
| `OPENAI_CHAT_AI_REASONING_EFFORT` | 비워 둠 | 추론 강도. 비어 있으면 `none`. 모델을 `gpt-6.1-sol`로 바꿀 때는 `low` |
| `CHAT_AI_TIMEOUT_MS` | 비워 둠 | AI 호출 한 번의 시간 한도(밀리초). 비어 있으면 `12000` |
| `CHAT_AI_MAX_REPLIES` | 비워 둠 | 대화 하나에서 AI를 부르는 횟수의 한도(버린 답 · 접수 안내로 대신한 답도 센다). 비어 있으면 `30` — 넘으면 직원 확인 필요로 넘긴다 |
| `CHAT_AI_DAILY_MAX` | 비워 둠 | 24시간 동안의 AI 호출 한도(비용 폭주 방지). 비어 있으면 `300` — 넘으면 지금 방식으로 동작한다 |
| `CHAT_AI_NOTICE` | 비워 둠 | `on`이면 채팅 화면에 "이곳에서는 자동 응대가 먼저 답하고, 예약은 모두 병원에서 확인합니다" 한 줄을 보인다. 병원 자문에서 고지가 필요하다고 나오면 켠다 |
| `CHAT_AI_OFFERS` | 비워 둠 | **제안형 응대 스위치**(2026-10-21 추가). 비어 있으면 꺼짐 — AI는 혜택을 "5% 할인"만 말한다. `test` = 손님 이름이 `ai-test`로 시작하는 문의에만, `on` = 모든 문의: 승인된 이달 구성 제안, 첫방문 체험가, 채팅 예약 혜택의 피부관리 · 수액(그날 결제 30만 원 이상). **병원 자문(U-4 · U-11) 전에는 `on`으로 두지 않는다.** 긴급 정지: 값을 지우고 재배포 — AI 응대는 그대로, 제안만 멈춘다 |
| `CHAT_AI_SUMMARY` | 비워 둠 | **AI 응대 요약 스위치**(2026-10-22 추가). 비어 있으면 켜짐 — 대화가 10분 멈추면 방에 요약 1개(손님이 물은 것 · AI가 답한 것 · 직원이 할 일). `off` = 요약만 멈춤(AI 답 전문은 그대로 방에 올라간다). 긴급 정지: `off`로 두고 재배포 |

> AI 1차 응대는 번역에 쓰는 `OPENAI_API_KEY`를 그대로 쓴다(새 키가 필요 없다). `CHAT_AI`를 켜기 전에 마이그레이션 043이 운영 DB에 적용돼 있어야 한다 — 적용 전이면 AI만 답하지 않고 나머지는 지금처럼 동작한다.

> 제안형 응대의 코드는 `CHAT_AI_OFFERS`가 꺼져 있어도 AI 기록에 마이그레이션 044의 컬럼을 쓴다. **044를 먼저 적용하고 코드를 배포한다** — 거꾸로 하면 AI가 답하지 않고 접수 안내로 대신한다(로그 `[chat ai] fallback: context_read_failed`).

> `SLACK_ROOM_PREFIX`는 2026-10-01부터 쓰지 않는다. 방 이름은 `10월01일-이름`(문의한 날짜 + 손님 이름)으로 만들어진다. Netlify에 값이 남아 있어도 해가 없고, 지워도 된다.

> **재촉 알림을 다시 켤 때** — 꺼져 있는 동안 답을 못 받은 대화가 쌓여 있으면, 켜는 순간 그 대화마다 5·12·30분 알림이 연달아 울린다. 켜기 전에 Claude에게 "기다리는 대화를 이미 알린 것으로 표시해 달라"고 하면 된다(`UPDATE chat_sessions SET escalation_level = 3 WHERE status = 'open' AND resolved_at IS NULL AND awaiting_since IS NOT NULL;`).

무작위 문자열 만들기 — PowerShell을 열고 아래를 붙여 넣으면 40자가 나옵니다. 그대로 복사해 `CHAT_OPS_SECRET` 값으로 넣습니다.

```powershell
-join ((48..57)+(65..90)+(97..122) | Get-Random -Count 40 | ForEach-Object {[char]$_})
```

3. 기존 값 `SLACK_BOT_TOKEN`, `SLACK_SIGNING_SECRET`, `SLACK_CHANNEL_ID` 는 **그대로 둡니다.** `SLACK_CHANNEL_ID`는 계속 `#해외문의`이며, 이 채널은 앞으로 "새 문의 / 완료 / 다시 열림" 한 줄 알림이 흐르는 피드가 됩니다.

> ⚠️ Netlify는 환경변수를 바꿔도 **다음 배포부터** 반영합니다. 값을 넣거나 고쳤으면 **Deploys → Trigger deploy → Deploy site** 를 한 번 누르세요. 무료 플랜이라 배포 비용은 없습니다.

## 8. H — 배포 첫날 확인 5가지

| 확인 | 방법 | 안 되면 |
|------|------|---------|
| 방 이름 | 새 문의 1건 → 방 이름이 `10월01일-이름` 꼴(문의한 날짜 + 손님 이름)인지 (2026-10-01 개정 — 한글 이름을 Slack이 받는 것은 시험 방에서 확인했다) | Slack이 이름을 거부하면 자동으로 예전 꼴 `chat-…`로 만들어집니다. Netlify **Logs → Functions** 의 `[slack rooms] name rejected` 줄을 Claude에게 보내 주세요 |

9. 방 안의 자동 알림(LIV 알림)은 한 줄씩만 올라옵니다(2026-10-02). 아래 두 가지는 화면에 따로 안내가 나오지 않으니 기억해 주세요.
   · 가격 문의에는 이벤트 링크가 자동으로 나갑니다(🎁 줄). 가격은 직접 답해 주세요.
   · 초록 막대(📱 연락처)가 뜬 손님은 답글 아래에 올라오는 "번역본 · 복사용" 글을 복사해 위챗·왓츠앱·메일로 보내 주세요.

## 10. 문제가 생기면

| 증상 | 원인 후보 | 할 일 |
|------|-----------|-------|
| 방이 안 생기고 예전처럼 `#해외문의` 스레드로 온다 | `#해외문의`에 사람 멤버가 없음 / `SLACK_ROOMS=off` / 재배포 안 함 / 권한 미추가 / §4 설정이 막힘 | Netlify **Logs → Functions** 에서 `[slack rooms] create failed:` 뒤의 단어를 확인 — `missing_scope`면 §1·§3, `restricted_action`이면 §4, 아무 로그도 없으면 §5·§6 재확인 |
| 방은 생겼는데 직원에게 안 보인다 | 초대 실패 | 같은 로그에서 `invite failed:` 확인. 코드가 그 방을 보관하고 스레드로 되돌립니다. 계정 비활성화 여부를 의심하세요 |
| 멘션이 회색 글자 `<@U…>`로 보인다 | 채널 멤버가 아닌 계정이 과거에 초대됨 / 계정 비활성화 | §5대로 `#해외문의` 멤버를 확인하고, 필요하면 그 손님 방에 직접 다시 초대하세요 |
| 재촉 알림(5·12·30분)이 안 온다 | 2026-10-02부터 꺼 둔 것 — 정상 | 다시 켜려면 §6의 `CHAT_ESCALATION` |
| "오늘 연락할 손님" 요약이 안 온다 | `CHAT_OPS_SECRET` 미설정 / 휴진일·영업시간 외 / 연락처를 남기고 기다리는 손님이 없음 | Netlify **Functions → chat-ops** 에서 최근 실행 로그 확인. 요약은 문 여는 시각과 마감 1시간 전에만 올라옵니다 |
| 자동 안내가 손님에게 안 보인다 | 같은 대기 구간의 두 번째 메시지 | 정상입니다. 직원이 답한 뒤 손님이 다시 쓰면 다시 나갑니다 |
| AI가 답하지 않고 접수 안내가 나간다 | `CHAT_AI`가 비어 있음 / `test`인데 손님 이름이 `ai-test`로 시작하지 않음 / 직원이 이미 답한 대화(직원 담당) / 043 미적용 / OpenAI 오류·시간 초과(방에 빨간 막대 `자동 응대가 답하지 못했습니다`) / 하루 한도 | Netlify **Logs → Functions** 에서 `[chat ai]` 로 시작하는 줄 확인 — `fallback: …`(답하지 못한 이유), `daily cap reached`(하루 한도), `session read failed`(043 미적용) |
| AI를 당장 꺼야 한다 | 틀린 안내가 나갔다 등 | Netlify에서 `CHAT_AI`를 지우거나 `off`로 바꾸고 재배포(약 2분). 그 순간부터 지금 방식(접수 안내 + 전원 멘션)으로 돌아간다. 이미 받은 가예약과 대화 기록은 그대로 남는다 |
| 가예약 알림(파란 막대)이 안 온다 | 날짜 · 시간(또는 "오전" 같은 메모) · 연락처 가운데 아직 받지 못한 것이 있다 | 정상입니다. 관리자 화면의 그 대화 머리말에 `🗓 가예약 받는 중`으로 보입니다. 손님이 마저 답하면 올라오고, 직원이 방에 답해 이어받아도 됩니다 |
| AI가 틀린 금액·지난달 프로모션을 말했다 | 근거 자료가 낡았다 | `2026-10-02-chat-ai-first-response-knowledge-update.md`대로 자료를 고친다. 급하면 먼저 `CHAT_AI=off` |
| 이모지만 보낸 손님에게 아무 답도 안 나간다 | AI가 맡은 대화에서는 내용 없는 글(이모지·문장부호뿐)에 답하지 않는다 | 정상입니다 |
| 배포 뒤 AI가 모든 문의에 접수 안내만 낸다 (로그 `fallback: context_read_failed`) | 마이그레이션 044를 적용하지 않고 제안형 응대 코드를 배포했다 | Claude에게 044 적용을 맡긴다(`scripts/_db/run-044.mjs`, 승인 뒤). 적용하면 다음 손님 글부터 AI가 다시 답한다 |
| AI가 구성을 제안하지 않는다 | `CHAT_AI_OFFERS`가 비어 있음 / `test`인데 손님 이름이 `ai-test`로 시작하지 않음 / 그 대화의 첫 답(첫 답에는 제안하지 않는다) / 손님이 관심을 보이지 않았거나 거절함 / 달이 바뀌어 조합이 가리키던 프로모션 줄이 없어짐 | 앞의 넷은 정상입니다. 마지막이면 `2026-10-02-chat-ai-first-response-knowledge-update.md` §2-1대로 조합 줄을 새 달에 잇는다 |
| 제안을 당장 꺼야 한다 | 틀린 구성 · 지킬 수 없는 혜택이 나갔다 등 | Netlify에서 `CHAT_AI_OFFERS`를 지우고 재배포(약 2분). AI 응대는 그대로 두고, 혜택은 "5% 할인"만 말한다. 이미 안내한 혜택은 그 손님에게 지켜 드릴지 원장님이 정한다 |

되돌리기: 언제든 Netlify에서 `SLACK_ROOMS` 값을 `off`로 바꾸고 재배포하면 **그 순간부터 새 문의는 지금 방식(스레드)** 으로 돌아갑니다. 이미 만들어진 방은 그대로 남아 계속 동작합니다.
