# 설문 답례품 받은 분 명단 (90일 동안 설문 링크 다시 안 보내기)

2026-11-24 · 사용자 요청: "상품 수령하신 분은 이후 90일간 추가 설문 링크를 안 보내야 한다. 받은 분 리스트를 확인할 수 있게."
사용자 결정: 적는 정보 = **이름 + 휴대폰 뒤 4자리**, 로컬 확인 뒤 **운영 반영까지**.

## 지금 상태 (바꾸기 전)

- `survey_gift_codes`(047)는 번호·발급일·「드림」 시각만 있다. 사람 정보가 없어 **누가 받았는지 확인할 수 없다**(익명 설계).
- 운영 실측(11/24): 번호 2건 발급, 「드림」 0건 → 거슬러 채울 명단 없음.

## 설계

1. **새 표 `survey_gift_recipients` (048)** — `id`, `name`(1~40자), `phone_last4`(숫자 4자리), `given_on`(날짜만).
   답례품 번호·응답 id·시각은 넣지 않는다 → 명단으로 답을 찾을 수 없다. RLS 서비스 롤만.
2. **「드림」 때 받은 분 필수** — `/api/admin/survey/gift` POST 가 `{ code, name, phone_last4 }` 를 받는다.
   받은 분 형식이 틀리면 번호를 바꾸지 않고 400. 번호 「드림」 처리 뒤 명단 저장이 실패하면
   번호는 드림 상태로 두고 `recipient_saved: false` → 화면이 「명단에 직접 추가해 주세요」 안내.
3. **명단 API `/api/admin/survey/recipients`** — GET(최근 90일, 받은 날 최신순), POST(직접 추가·받은 날 지정 가능,
   오늘~89일 전까지), DELETE `?id=`(잘못 적은 줄). GET 할 때 90일 지난 줄을 지운다.
4. **규칙** — 받은 날 + 90일 = 「다시 보낼 수 있는 날」. 그 전날까지 명단에 남는다(`GIFT_RECIPIENT_HOLD_DAYS`).
   서버는 숫자 정확히 4자리만 받는다. 화면 입력칸은 숫자만 남기고 **마지막 4자리**를 유지한다 —
   직원이 전체 번호(010-1234-5678)를 쳐도 「5678」만 남고, 전체 번호는 서버로 가지 않는다.
5. **화면 `/admin/survey`** — 「답례품 번호 확인」 옆에 「답례품 받은 분 (최근 90일)」: 이름·뒤 4자리 검색,
   찾는 분이 없으면 「명단에 없어요 — 보내도 됩니다」, 줄마다 받은 날·다시 보낼 수 있는 날·지우기(화면 안 확인),
   「직접 추가」. 「드림」 칸에 이름·뒤 4자리 입력칸을 붙인다.

## 익명성

명단과 번호·응답은 키로 연결되지 않는다. 다만 응답이 하루 1건 수준이라 날짜를 맞춰 보면 짐작은 가능하다 —
운영 안내의 「제출 시각으로 누가 썼는지 찾지 않기」 규칙은 계속 필요하다. 설문 화면 「이름·연락처는 받지 않아요」는
설문 자체엔 여전히 맞으므로 바꾸지 않는다.
