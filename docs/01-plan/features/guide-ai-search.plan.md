# Plan: 사용가이드 AI 검색 기능

> **Feature**: guide-ai-search
> **Created**: 2026-02-08
> **Status**: Plan Phase

---

## 1. 배경 및 문제

### 현재 상황
- 사용가이드 페이지(`/admin/guide`)에 **14개 섹션, 718줄**의 방대한 콘텐츠 존재
- 목차(TOC) 클릭으로 섹션 이동은 가능하지만, 구체적인 질문에 대한 답을 찾으려면 전체를 읽어야 함
- 예: "환불은 어떻게 하나요?" → 14개 섹션 중 어디에 있는지 직접 찾아야 함

### 사용자 페인포인트
- 원하는 기능이 어느 메뉴에 있는지 모름
- 특정 작업 방법을 찾으려면 전체 가이드를 스크롤해야 함
- 신규 직원이 시스템을 빠르게 익히기 어려움

---

## 2. 목표

**"질문을 입력하면 가이드 콘텐츠에서 맞춤 답변을 즉시 제공"**

- 자연어 질문 → 관련 가이드 섹션/단계를 맞춤 발췌하여 답변
- 외부 AI API 없이 **클라이언트 사이드 로컬 검색**으로 구현 (비용 0원)
- 기존 가이드 콘텐츠를 활용한 키워드 매칭 + 유사도 기반 검색

---

## 3. 구현 방식

### 3.1 아키텍처: 로컬 키워드 검색 (외부 API 없음)

```
[사용자 질문 입력]
        ↓
[키워드 추출 + 정규화]
        ↓
[가이드 데이터 인덱스 검색]
  - 섹션별 키워드 매칭
  - 제목/내용/시나리오/FAQ 가중 스코어링
        ↓
[결과 랭킹 + 상위 N개 표시]
  - 관련 섹션 하이라이트
  - 구체적 단계(Step) 발췌
  - 해당 섹션으로 이동 버튼
```

### 3.2 검색 데이터 구조

가이드 콘텐츠를 검색 가능한 구조화 데이터로 변환:

```typescript
interface GuideSearchItem {
  sectionId: string;        // 'consultations', 'inventory' 등
  sectionTitle: string;     // '📋 상담관리'
  type: 'scenario' | 'step' | 'feature' | 'faq' | 'tip';
  title: string;            // 시나리오명, 단계명, FAQ 질문
  content: string;          // 상세 내용
  keywords: string[];       // 검색 키워드 (한글 + 영어)
  path?: string;            // 관련 관리자 페이지 경로
}
```

### 3.3 검색 알고리즘

1. **키워드 토큰화**: 사용자 입력을 공백 기준 분리 + 조사 제거
2. **매칭 스코어**:
   - 제목 일치: 10점
   - 키워드 일치: 5점
   - 내용 포함: 2점
   - FAQ 질문 일치: 8점 (직접적 질문-답변이므로 높은 가중치)
3. **결과 정렬**: 스코어 내림차순, 상위 5개 표시

### 3.4 UI 디자인

```
┌─────────────────────────────────────────────────────┐
│ 🔍 무엇이 궁금하신가요?                              │
│ ┌─────────────────────────────────────────────────┐ │
│ │ 환불은 어떻게 하나요?                    [검색]  │ │
│ └─────────────────────────────────────────────────┘ │
│                                                     │
│ 💬 검색 결과 (3건)                                  │
│                                                     │
│ ┌─ 💰 매출관리 ──────────────────────────────────┐ │
│ │ 시나리오 B: 환불 처리                            │ │
│ │ ① 결제완료 건에서 환불 클릭                      │ │
│ │ ② 확인 팝업에서 '환불' 선택하면 상태 변경        │ │
```

## 4. 주요 기능

### F1. 검색 입력 UI
- 가이드 페이지 상단, 목차 위에 검색바 배치
- placeholder: "무엇이 궁금하신가요? 예: 환불 방법, 재고 입고, 음성 인식..."
- Enter 키 또는 검색 버튼으로 검색
- 입력 시 실시간 검색 (debounce 300ms)

### F2. 검색 결과 표시
- 결과 카드: 섹션 아이콘 + 제목 + 매칭 내용 발췌 + 이동 버튼
- 결과 없을 때: "검색 결과가 없습니다. 다른 키워드로 검색해보세요." 안내
- 검색 결과 클릭 시 해당 섹션으로 스크롤 이동 + 하이라이트

### F3. 추천 검색어 (Quick Tags)
- 검색바 하단에 자주 찾는 키워드 태그 표시
- 태그 클릭 시 자동 검색 실행
- 예시 태그: "콜백 처리", "재고 입고", "음성 인식", "CSV 내보내기", "알림 발송", "환불", "이벤트 등록"

### F4. FAQ 우선 매칭
- 기존 FAQ 8개 항목을 검색 결과에서 우선 노출
- 질문형 입력 시 FAQ와 직접 매칭

- 별도 API 호출 없음 (클라이언트 사이드 완결)

## 6. 구현 순서

1. **검색 데이터 인덱스 정의** - 14개 섹션의 시나리오/단계/기능/FAQ를 구조화 배열로 작성
2. **검색 알고리즘 구현** - 키워드 토큰화 + 매칭 스코어 계산 함수
3. **검색 UI 컴포넌트** - 검색바 + 결과 카드 + 추천 태그
4. **가이드 페이지에 통합** - 목차 위에 검색 영역 배치
5. **테스트** - 다양한 질문으로 검색 품질 확인

## 7. 기술 제약 및 결정

| 항목 | 결정 | 이유 |
|------|------|------|
| AI API (OpenAI 등) | 사용 안 함 | 비용, 레이턴시, API 키 관리 부담 |
| 벡터 검색 | 사용 안 함 | 가이드 콘텐츠 규모가 작아 키워드 검색으로 충분 |
| 서버 사이드 검색 | 사용 안 함 | 가이드 내용이 코드에 하드코딩되어 있어 클라이언트 검색이 적합 |
| 형태소 분석기 | 사용 안 함 | 한글 키워드 + 수동 동의어 매핑으로 충분한 정확도 |

## 8. 예상 검색 시나리오

| 사용자 질문 | 예상 결과 |
|-------------|-----------|
| "환불 어떻게 해요?" | 매출관리 > 시나리오 B: 환불 처리 |
| "재고 부족" | 재고관리 > 시나리오 B: 부족 재고 입고 처리 |
| "음성 인식 안돼요" | FAQ: 음성 인식이 안 돼요 + 음성 노트 > 브라우저 호환성 |
| "콜백 처리" | 상담관리 > 시나리오 B: 콜백 처리 |
| "목표 매출 설정" | 설정 > 병원 정보 탭 + FAQ: 목표 매출 설정 위치 |
| "새 이벤트 만들기" | 이벤트관리 > 시나리오: 새 이벤트 등록 |
| "CSV" | 상담관리/매출관리/알림관리 CSV 관련 기능들 |
| "앱 설치" | 시스템 개요 > PWA 설치 팁 + FAQ: 별도 앱 설치 여부 |
| "동시 접속" | FAQ: 여러 명이 동시에 사용할 수 있나요? |
| "알림 발송 방법" | 알림관리 > 시나리오 A: 시술 후 재방문 알림 발송 |

## 9. 성공 기준

- [ ] 가이드 페이지 상단에 검색바 표시
- [ ] 키워드 입력 시 300ms 이내 결과 표시
- [ ] 위 10개 시나리오에서 80% 이상 정확한 결과 반환
- [ ] 결과 카드 클릭 시 해당 섹션으로 스크롤 이동
- [ ] 추천 검색어 태그 클릭 시 자동 검색
- [ ] 모바일에서도 검색 UI 정상 동작
- [ ] 기존 가이드 콘텐츠 렌더링에 영향 없음
