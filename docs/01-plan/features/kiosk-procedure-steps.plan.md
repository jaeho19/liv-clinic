## 1. 배경 및 목표

### 현재 문제
1. **시술 선택이 평면적**: 써마지 FLX 600, 써마지 FLX 900이 별도 항목으로 나열됨. 시술 종류가 늘어나면 스크롤이 길어지고 선택이 번거로움
2. **용량/옵션 선택 불가**: 리브 홈페이지 기준으로 울쎄라(트랜스듀서별), 써마지(샷수별), 슈링크(카트리지별) 등 각 시술의 세부 옵션을 반영하지 못함
3. **사용 기록 실시간 확인 불가**: 차감 후 기록이 즉시 화면에 보이지 않아 당일 누가 어떤 시술을 했는지 한눈에 파악 불가

### 목표
- **2단계 시술 선택**: 1단계(시술 종류) → 2단계(용량/옵션) → 물품 자동 로드
- **일별 사용 로그**: 당일 기록을 키오스크 하단에 실시간 표시, 날짜 변경 시 자동 갱신
- **리브 홈페이지 시술 정보 반영**: 실제 제공하는 시술 메뉴 기반으로 재구성

## 3. 기능 상세

### 3-1. 2단계 시술 선택 (KioskView 개선)

**현재 흐름**: 시술명 탭 → 물품 자동 로드 → 수량 조절 → 차감
**변경 흐름**: 시술 카테고리 탭 → 옵션 선택 (해당되는 경우) → 물품 자동 로드 → 수량 조절 → 차감

#### 데이터 구조 변경

```typescript
// 새로운 시술 체계 (PROCEDURE_NAMES 대체)
interface ProcedureType {
  id: string;                    // 'ulthera', 'thermage', etc.
  name: string;                  // '울쎄라 프라임'
  category: 'lifting' | 'antiaging' | 'skinbooster';
  options: ProcedureOption[];    // 빈 배열이면 바로 물품 로드
}

interface ProcedureOption {
  id: string;                    // 'thermage_600', 'ulthera_full'
  label: string;                 // '600샷', '전안면'
  recipeName: string;            // DB procedure_recipes.procedure_name과 매칭
}
```

#### UI 변경

**좌측 패널 (1단계)**:
- 카테고리별 그룹핑 유지 (리프팅, 안티에이징, 스킨부스터)
- 시술 종류만 표시 (울쎄라, 써마지, 덴서티...)
- 선택 시 옵션이 있으면 2단계 표시, 없으면 바로 물품 로드

**2단계 (옵션 선택)**:
- 좌측 패널 내부에서 인라인 표시 (선택한 시술 아래에 pill 버튼)
- 또는 좌측 패널 상단에 선택된 시술 + 옵션 행 표시
- 옵션 pill 클릭 → 해당 레시피의 물품 자동 로드

### 3-2. 일별 사용 기록 표시

**키오스크 하단에 당일 기록 섹션 추가**:

```
┌─────────────────────────────────────────────────┐
│ 오늘의 사용 기록 (2/14)                    5건   │
├─────────────────────────────────────────────────┤
│ 14:30  써마지 FLX 600  홍길동  간호사A  3개 품목  │
│ 13:15  울쎄라 전안면    김철수  간호사B  5개 품목  │
│ 11:00  보톡스 제오민    이영희  간호사A  2개 품목  │
│ 10:30  필러 볼벨라      박지훈  간호사B  1개 품목  │
│ 09:45  써마지 FLX 900  최수현  간호사A  4개 품목  │
└─────────────────────────────────────────────────┘
```

#### 핵심 동작
1. **당일 기록만 표시**: 오늘 날짜의 `inventory_transactions` (tx_type='use')만 조회
2. **차감 완료 시 자동 추가**: 차감 성공 후 목록 실시간 갱신
3. **날짜 변경 시 자동 갱신**: 자정 넘어가면 새 날짜 기록만 표시
4. **이전 기록 보존**: DB에 영구 저장 (inventory_transactions 테이블), overview의 "사용 이력" 탭에서 날짜별 조회 가능

#### API 활용
- 기존 `GET /api/admin/inventory/transactions?type=use&dateFrom=2026-02-14&dateTo=2026-02-14` 활용
- 추가 API 불필요 (기존 필터 파라미터로 충분)

## 5. 검증 방법

1. **빌드**: `npm run build` 에러 없음
2. **시술 선택 흐름**: 써마지 탭 → 600샷 옵션 → 물품 자동 로드 → 차감 → 하단 기록 갱신
3. **옵션 없는 시술**: 덴서티 탭 → 바로 물품 로드 (2단계 스킵)
4. **일별 기록**: 차감 후 하단 목록에 즉시 추가 확인
5. **날짜 변경**: 다음 날 접속 시 이전 날 기록 안 보이고, 당일만 표시
6. **이전 기록 접근**: overview "사용 이력" 탭에서 날짜 필터로 확인 가능

## 6. 제약 사항

- `PROCEDURE_NAMES`는 기존 recipe와의 호환을 위해 삭제하지 않음 (병행 유지)
- 새 시술 옵션 추가 시 `PROCEDURE_TYPES` 상수만 수정하면 됨
- DB 스키마 변경 없음 (기존 `procedure_recipes.procedure_name`으로 매칭)
