## 1. 현재 상태 분석

### 1-1. 관리자 시스템 구조
- **프레임워크**: Next.js 16 App Router
- **백엔드**: Supabase (PostgreSQL) + 직접 postgres 연결 (`db.ts`)
- **인증**: Supabase Auth (이메일/비밀번호)
- **주요 모듈**: 대시보드, 상담관리, 재고관리, 이벤트관리, 팝업관리, 운영추적, 알림관리, 리포트, 설정

### 1-2. 확인된 문제점

| # | 문제 | 원인 | 심각도 |
|---|------|------|--------|
| 1 | 재고관리 "품목 목록을 불러오지 못했습니다" | `DATABASE_URL` 환경변수 미설정 or DB 테이블 미존재. 재고 API(`/api/admin/inventory`)가 `postgres` 라이브러리(db.ts)로 직접 연결하는데, Supabase가 아닌 별도 `DATABASE_URL`이 필요 | **높음** |
| 2 | 관리자에서 이벤트 삭제해도 홈페이지에 반영 안 됨 | 공개 이벤트 페이지(`/events`)에 **하드코딩된 EVENTS 상수가 fallback**으로 존재. API에서 삭제해도 `constants.ts`의 상수가 그대로 표시됨. 병합 로직이 API 결과 + 상수 데이터를 합치는 구조 | **높음** |
| 3 | 음성→텍스트 상담 기록 기능 없음 | 신규 기능 요청 | **중간** |

## 2. 해결 방안

### 문제 1: 재고관리 DB 연결 오류

**근본 원인**:
- 재고 API는 `getDb()`를 사용하여 `postgres` 라이브러리로 직접 SQL 쿼리
- `DATABASE_URL` 환경변수가 프로덕션 환경에 설정되어 있지 않음
- 다른 API들(이벤트, 팝업 등)은 Supabase Client를 사용

**해결 방법 A (권장): Supabase Client로 통일**
- 재고 관련 API 6개를 모두 Supabase Client 방식으로 마이그레이션
- `createAdminClient()`(service role)를 사용하여 RLS 우회
- 장점: 환경변수 1세트만 관리, 일관성, Supabase 대시보드에서 모니터링 가능
- 작업량: API route 6개 수정

**해결 방법 B: DATABASE_URL 환경변수 설정**
- Supabase 프로젝트의 PostgreSQL 연결 URL을 `DATABASE_URL`로 설정
- Netlify 환경변수에 추가
- 장점: 코드 변경 최소
- 단점: 두 가지 DB 연결 방식 혼용, connection pool 이중 관리

### 문제 2: 이벤트 삭제 후 홈페이지 미반영

**근본 원인**:
```
events/page.tsx의 로직:
1. API에서 이벤트 fetch
2. API 이벤트 ID 목록 생성
3. constants.ts의 EVENTS 중 API에 없는 것을 추가 (병합)
→ 즉, DB에서 삭제해도 constants.ts에 있으면 항상 표시됨
```

**해결 방법 A (권장): 상수 데이터를 DB에 마이그레이션**
- `constants.ts`의 EVENTS 데이터를 Supabase events 테이블에 삽입
- 공개 이벤트 페이지를 API-only로 변경 (상수 fallback 제거)
- API 실패 시 빈 목록 표시 + 에러 메시지
- 장점: 관리자에서 완전한 제어권, 실시간 반영
- 작업: SQL seed 스크립트 + 프론트엔드 수정

**해결 방법 B: 삭제 목록을 DB에 관리**
- "비공개" 처리된 이벤트 slug 목록을 DB에 저장
- 상수 데이터 표시 시 비공개 목록 필터링
- 장점: 기존 코드 대부분 유지
- 단점: 복잡한 로직, 유지보수 어려움

### 문제 3: 음성→텍스트 상담 기록 (STT 기능)

**요구사항**: 모바일에서 직원이 말로 환자 기록을 입력하면 정해진 템플릿에 맞게 텍스트로 변환

**해결 방법: Web Speech API + 구조화 템플릿**

#### 구현 구조:
```
[모바일 음성 입력] → [Web Speech API (STT)] → [텍스트 파싱] → [템플릿 구조화] → [저장]
```

#### 단계별 계획:

**Step 1: 상담 메모 템플릿 정의**
```
템플릿 예시:
- 환자명: ___
- 상담 유형: [초진/재진/시술후관리]
- 주요 호소: ___
- 상담 내용: ___
- 권장 시술: ___
- 예상 비용: ___
- 다음 단계: [예약확정/재연락/검토중]
- 메모: ___
```

**Step 2: 음성 입력 컴포넌트 개발**
- `VoiceNoteInput` 컴포넌트 생성
- Web Speech API (`SpeechRecognition`) 사용 (Chrome/Edge/Safari 지원)
- 한국어 인식 모드 (`lang: 'ko-KR'`)
- 실시간 텍스트 표시 + 수정 가능

**Step 3: 활용 위치**
- 상담 관리 페이지 (`/admin/consultations`) - 상담 메모 입력
- 환자 시술 기록 (`/admin/patient-treatments`) - 시술 후 기록
- 대시보드 퀵 메모 - 간단한 환자 노트

**Step 4: 템플릿 기반 구조화**
- 음성으로 "환자명 김OO, 상담유형 초진, 주요호소 팔자주름 개선, ..." 식으로 입력
- 키워드 기반 파싱 → 적절한 필드에 자동 매핑
- 또는 단계별 입력: 각 필드를 순서대로 음성으로 안내하며 입력

## 3. 관리자 페이지 사용 가이드 & 개선 제안

### 3-1. 현재 주요 기능 활용법

| 메뉴 | 용도 | 활용 팁 |
|------|------|---------|
| **대시보드** | 일일 현황 파악 | 매일 오전 출근 시 확인. 오늘의 콜백, 신규 상담 확인 |
| **상담 관리** | 리드 추적 | 상태 변경으로 파이프라인 관리. CSV 내보내기로 주간 보고 |
| **이벤트 관리** | 홈페이지 이벤트 | 이벤트 생성→게시→종료 전체 사이클 관리 |

| **재고 관리** | 의료품 재고 | (수정 후) 품목별 재고 추적, 레시피 기반 자동 차감 |
| **리포트** | 통계/분석 | 상담 전환율, 시술 통계, 의사별 실적 |
| **설정** | 마스터 데이터 | 시술 종류, 직원 관리, 진료 정보 |

## 5. 기술적 고려사항

### Web Speech API 호환성
- Chrome/Edge: 완전 지원
- Safari (iOS): 지원 (iOS 14.5+)
- Firefox: 미지원 → 수동 입력 폴백 필요
- 보안: HTTPS 필수 (liv-clinic.net은 HTTPS이므로 OK)

### Supabase 마이그레이션 시 주의점
- 재고 API의 SQL 쿼리를 Supabase Query Builder로 변환
- 조건부 WHERE 절 → `.eq()`, `.ilike()`, `.lte()` 등으로 변환
- RLS 정책 확인 (admin client는 service role로 우회)

### 이벤트 마이그레이션 시 데이터 무결성
- `constants.ts`의 6개 이벤트를 DB에 seed
- 다국어 데이터 (ko, en, ja, zh) 모두 변환
- gallery_images 배열 → Supabase JSON 컬럼
- 마이그레이션 후 상수 데이터에서 EVENTS 배열 제거 or deprecated 마킹
