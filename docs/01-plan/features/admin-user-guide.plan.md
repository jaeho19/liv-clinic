## 1. 프로젝트 개요

### 1.1 목적
LIV 성형외과 관리자 페이지의 모든 기능을 상세하게 문서화하여, 신규 직원이나 관리자가 쉽게 시스템을 이해하고 사용할 수 있도록 합니다.

### 1.2 대상 독자
- 병원 관리자 (원장, 실장)
- 접수/상담 직원
- 간호사/의료진
- 시스템 관리자

### 1.3 접속 방법
- **URL**: `https://livps.co.kr/admin` (또는 `localhost:3000/admin`)
- **인증**: Supabase 이메일/비밀번호 로그인
- 로그인 후 자동으로 대시보드로 이동

---

## 2. 전체 메뉴 구조

```
관리자 시스템
├── 🔐 로그인 (/admin/login)
│
├── 📊 병원 운영
│   ├── 대시보드 (Dashboard)          - 전체 현황 한눈에 보기
│   ├── 상담관리 (Consultations)      - 상담 접수/관리/추적
│   ├── 운영현황 (Operations)         - 당일 시술 현황 (플로어맵/칸반)
│   ├── 재고관리 (Inventory)          - 시술 재고/소모품 관리
│   ├── 알림관리 (Notifications)      - 환자 팔로업 알림
│   ├── 리포트 (Reports)              - 월간 경영 분석
│   └── 매출관리 (Revenue)            - 일별/주별/월별 매출 추적
│
├── 🌐 홈페이지 관리
│   ├── 이벤트관리 (Events)           - 프로모션/이벤트 등록
│   └── 팝업관리 (Popups)             - 웹사이트 팝업 관리
│
└── ⚙️ 시스템
    └── 설정 (Settings)
        ├── 시술 마스터                - 시술 항목 관리
        ├── 직원 관리                  - 의료진/스태프 관리
        ├── 감사 로그                  - 시스템 활동 이력
        └── 기본정보                   - 병원 기본 설정
```

## 3. 섹션별 상세 기능 설명

### 3.1 대시보드 (Dashboard)

**경로**: `/admin/dashboard`
**역할**: 병원 운영 전체 현황을 한눈에 파악

#### 주요 기능

| 기능 | 설명 | 활용 시점 |
|------|------|-----------|
| **7개 KPI 카드** | 오늘 상담, 콜백 예정, 운영 건수, 월간 상담, 미발송 알림, 활성 이벤트, 활성 팝업 | 출근 시 첫 화면으로 확인 |
| **7일 트렌드 차트** | 최근 7일간 상담/시술 추이 바 차트 | 주간 동향 파악 |
| **알림 배너** | 미발송 알림이 있을 때 상단에 경고 | 즉시 처리 필요 건 인지 |
| **주간 요약** | 이번 주 통계 요약 | 주간 미팅 자료 |
| **오늘의 콜백** | 오늘 콜백 예정인 환자 목록 | 상담사 업무 우선순위 |
| **최근 상담 5건** | 가장 최근 접수된 상담 | 신규 상담 빠른 확인 |

#### 사용 가이드
1. **매일 아침**: 대시보드에서 오늘의 상담 건수와 콜백 예정을 확인합니다.
2. **알림 배너**: 미발송 알림이 있으면 `알림관리` 페이지로 이동하여 처리합니다.
3. **트렌드 차트**: 7일간 상담/시술 추이가 하락하면 이벤트 등록이나 마케팅 강화를 검토합니다.

#### 연관 섹션
- KPI 카드 클릭 → **상담관리**, **운영현황**, **알림관리**, **이벤트관리** 등으로 이동 가능
- 콜백 위젯 → **상담관리**의 콜백 필터와 연동

### 3.2 상담관리 (Consultations)

**경로**: `/admin/consultations`
**역할**: 환자 상담 접수부터 완료까지 전체 파이프라인 관리

#### 상담 상태 흐름

```
신규(new) → 콜백예정(callback_scheduled) → 예약완료(reserved) → 완료(completed)
         ↘ 부재중(no_answer) → 재연락(re_contact) ↗
         ↘ 노쇼(no_show)
         ↘ 취소(cancelled)
```

#### 주요 기능

| 기능 | 설명 | 활용 시점 |
|------|------|-----------|
| **상태별 탭 필터** | 전체/신규/콜백예정/부재중/재연락/예약/노쇼/완료/취소 | 업무별 상담 분류 |
| **검색** | 이름/전화번호로 검색 | 환자 빠른 조회 |
| **담당자 필터** | 특정 상담사에게 배정된 건만 보기 | 개인 업무 관리 |
| **오늘 콜백만 보기** | 토글로 오늘 콜백 예정 건만 필터링 | 당일 우선 업무 |
| **벌크 액션** | 여러 건 선택 → 상태 일괄 변경, 담당자 일괄 배정 | 대량 처리 시 |
| **인라인 편집** | 담당자, 다음 연락일, 예산 범위, 메모 즉시 수정 | 빠른 정보 업데이트 |
| **상세 보기** | 행 클릭으로 확장하여 전체 정보 확인 | 상담 상세 검토 |
| **CSV 내보내기** | 현재 필터 기준으로 CSV 다운로드 | 보고서/분석 자료 |
| **음성 메모** | 마이크 버튼으로 음성을 텍스트로 변환 (한국어) | 전화 상담 중 메모 |
| **감사 로그** | 모든 변경 사항 자동 기록 | 이력 추적/감사 |
| **페이지네이션** | 20건 단위로 페이지 이동 | 대량 데이터 탐색 |

#### 사용 시나리오

**시나리오 1: 신규 상담 처리**
1. `신규` 탭에서 새로 들어온 상담을 확인합니다.
2. 담당자를 배정합니다 (인라인 편집).
3. 전화를 걸어 상담합니다.
4. 상태를 `콜백예정` 또는 `예약완료`로 변경합니다.
5. 다음 연락일을 설정합니다.

**시나리오 2: 일일 콜백 처리**
1. `오늘 콜백만 보기`를 활성화합니다.
2. 순서대로 전화하며 메모를 음성 입력합니다.
3. 결과에 따라 상태를 업데이트합니다.

**시나리오 3: 주간 보고**
1. 기간별 필터를 적용합니다.
2. CSV 내보내기로 데이터를 다운로드합니다.
3. 상태별 건수를 리포트에 활용합니다.

#### 연관 섹션
- 상담 → 예약 완료 후 **운영현황**에서 당일 시술 관리
- 상담 통계 → **리포트**의 상담 퍼널 분석
- 상담 → 시술 완료 후 **알림관리**에서 팔로업

### 3.3 운영현황 (Operations)

**경로**: `/admin/operations`
**역할**: 당일 시술실 현황 실시간 관리 (수술실 OS 개념)

#### 뷰 모드

| 모드 | 설명 | 활용 시점 |
|------|------|-----------|
| **플로어맵** | 병원 평면도에서 각 룸 상태를 시각화 | 전체 병원 현황 파악 |
| **칸반 보드** | 대기→상담→마취→시술/스킨케어→완료 5단계 | 환자 흐름 관리 |

#### 주요 기능

| 기능 | 설명 |
|------|------|
| **케이스 등록** | 환자명, 시술 유형, 담당의, 시술명, 소요시간 입력 |
| **상태 관리** | WAITING(대기) → IN_PROGRESS(진행중) → COMPLETED(완료) |
| **위치 추적** | LOUNGE(라운지) / ROOM(시술실) 위치 관리 |
| **자동 타이머** | 시술 시작 후 경과 시간 자동 표시 (30초 갱신) |
| **통계 카드** | 활성/대기/완료/전체 건수 실시간 표시 |
| **시술 유형** | 상담(CONSULT), 마취(ANESTHESIA), 시술(PROCEDURE), 스킨케어(SKINCARE) |

#### 사용 시나리오

**시나리오: 환자 동선 관리**
1. 환자 도착 → `케이스 등록` (대기 상태)
2. 상담실 배정 → `위치: ROOM` + `상태: 진행중`
3. 상담 완료 → `라운지로 이동`
4. 시술실 배정 → `시작` 버튼
5. 시술 완료 → `완료` 버튼

#### 연관 섹션
- **상담관리** → 예약 환자가 당일 운영현황에 등록
- **재고관리** → 시술 시 사용되는 재고 자동/수동 차감
- **매출관리** → 시술 완료 시 결제 처리
- **알림관리** → 시술 완료 후 팔로업 알림 예약

### 3.4 재고관리 (Inventory)

**경로**: `/admin/inventory`
**역할**: 시술 재료/소모품 재고 추적 및 관리

#### 3개 탭 구성

| 탭 | 설명 |
|----|------|
| **재고 현황** | 전체 재고 목록, 현재 수량, 상태 |
| **사용 이력** | 재고 입출고 기록 (날짜, 유형, 수량, 환자) |
| **입고 관리** | 재입고 처리 |

#### 3개 뷰 모드 (재고 현황 탭)

| 모드 | 설명 |
|------|------|
| **테이블 뷰** | 전통적인 표 형태 |
| **카드 뷰** | 카드 그리드 레이아웃 |
| **그룹 뷰** | 카테고리별 그룹핑 |

#### 주요 기능

| 기능 | 설명 |
|------|------|
| **재고 대시보드** | 전체/정상/부족/소진 항목 수 카드 |
| **알림 배너** | 재고 부족/소진 항목 경고 (닫기/해제 가능) |
| **필터** | 검색, 카테고리, 재고 상태 |
| **상세 패널** | 항목 클릭 시 최근 15건 거래 이력 |
| **항목 추가** | 이름, 카테고리, 단위, 현재/최소 재고, 가격, 공급업체, 보관 참고사항 |
| **재고 사용** | 환자명, 차트번호, 시술 선택(레시피 자동 로드), 사용 항목, 간호사 확인 |
| **입출고** | 입고/출고 처리 (사유 입력) |
| **레시피 시스템** | 시술별 기본 사용 재료 자동 로드 |

#### 재고 상태 구분
- **정상 (Normal)**: 현재 수량 > 최소 수량
- **부족 (Low)**: 현재 수량 ≤ 최소 수량 (주의)
- **소진 (Out)**: 현재 수량 = 0 (긴급)

#### 사용 시나리오

**시나리오 1: 시술 전 재고 사용 등록**
1. `재고 사용` 모달을 엽니다.
2. 환자명과 차트번호를 입력합니다.
3. 시술을 선택하면 레시피가 자동 로드됩니다.
4. 실제 사용량을 조정합니다.
5. 간호사 확인 후 등록합니다.

**시나리오 2: 재입고 처리**
1. `입고 관리` 탭으로 이동합니다.
2. 항목을 선택하고 입고 수량과 사유를 입력합니다.
3. 재고가 자동으로 업데이트됩니다.

**시나리오 3: 재고 부족 대응**
1. 알림 배너에서 부족 항목을 확인합니다.
2. 공급업체에 발주합니다.
3. 물품 도착 시 입고 처리합니다.

#### 연관 섹션
- **운영현황** → 시술 시 재고 차감 연동
- **설정 > 시술 마스터** → 시술별 레시피(사용 재료) 설정
- **리포트** → 재고 소모량 분석 데이터

### 3.5 알림관리 (Notifications)

**경로**: `/admin/notifications`
**역할**: 시술 후 환자 팔로업 알림 관리

#### 주요 기능

| 기능 | 설명 |
|------|------|
| **KPI 카드** | 오늘 발송 대상, 미발송 건수, 이번 주 예정 |
| **알림 배너** | 미처리 알림 경고 |
| **환자 치료 기록** | 검색/필터로 대상 환자 조회 |
| **발송 워크플로우** | 채널 선택(카카오/SMS/전화) → 담당자 확인 → 메모 → 발송/스킵 |

#### 하위 페이지

| 페이지 | 경로 | 설명 |
|--------|------|------|
| **알림 템플릿** | `/notifications/templates` | 알림 메시지 템플릿 관리 (CRUD) |
| **발송 이력** | `/notifications/history` | 과거 발송 기록 조회 |

#### 사용 시나리오

**시나리오: 시술 후 팔로업**
1. 환자가 시술을 받으면 치료 기록을 등록합니다.
2. 설정된 주기(예: 3일 후)에 알림이 대시보드에 나타납니다.
3. 알림 대상 환자에게 카카오/SMS/전화로 연락합니다.
4. 결과를 기록하고 `발송완료` 또는 `스킵` 처리합니다.

#### 연관 섹션
- **상담관리** → 상담 완료 → 시술 후 팔로업 알림
- **운영현황** → 시술 완료 → 자동 팔로업 대상 등록
- **설정 > 기본정보** → 알림 설정 (콜백 리마인더, 재고 부족 알림, 신규 상담 알림)

### 3.6 리포트 (Reports)

**경로**: `/admin/reports`
**역할**: 월간 경영 분석 및 성과 리포트

#### 주요 기능

| 기능 | 설명 |
|------|------|
| **기간 선택** | 연도/월 드롭다운으로 조회 기간 설정 |
| **전월 비교** | 체크박스로 전월 대비 비교 활성화 |
| **4개 KPI 카드** | 월 매출(목표 달성률%), 전환율, 시술 건수, 건당 평균 매출 + 전월 대비 증감% |
| **상담 퍼널** | 접수 → 연락 → 예약 → 완료 → 노쇼 단계별 분석 |
| **일별 트렌드** | 7일 바 차트 (상담 vs 시술) |
| **시술 통계 테이블** | 시술별 매출 순위 |
| **의사 성과** | 의사별 상담수, 시술수, 매출, 전환율 |
| **CSV 내보내기** | KPI, 퍼널, 시술, 의사, 일별 데이터 통합 CSV |

#### 사용 시나리오

**시나리오: 월간 경영 회의**
1. 해당 월을 선택합니다.
2. `전월 비교`를 활성화하여 추이를 확인합니다.
3. KPI 카드에서 목표 달성률을 확인합니다.
4. 상담 퍼널에서 이탈 구간을 파악합니다.
5. CSV를 내보내 회의 자료로 활용합니다.

#### 연관 섹션
- **상담관리** → 상담 데이터가 퍼널 분석의 원천
- **운영현황** → 시술 건수/유형 데이터
- **매출관리** → 매출 데이터 원천
- **설정 > 기본정보** → 목표 매출 설정 (달성률 계산 기준)

### 3.7 매출관리 (Revenue)

**경로**: `/admin/revenue`
**역할**: 일별/주별/월별 매출 추적 및 결제 관리

#### 주요 기능

| 기능 | 설명 |
|------|------|
| **기간 토글** | 오늘 / 이번 주 / 이번 달 |
| **4개 KPI 카드** | 당일 매출, 주간 매출, 월간 매출, 건당 평균 |
| **7일 매출 트렌드** | 바 차트로 일별 매출 시각화 |
| **결제 상태 탭** | 전체/완료/대기/환불 |
| **거래 테이블** | 날짜, 환자명, 시술, 금액, 할인, 순금액, 결제방법, 상태 |
| **인라인 결제 처리** | 대기 건에 결제금액+방법 입력 후 확인 |
| **환불 처리** | 완료된 결제에 환불 버튼 |
| **CSV 내보내기** | 거래 내역 다운로드 |

#### 결제 상태 흐름
```
대기(pending) → 완료(completed) → 환불(refunded)
```

#### 사용 시나리오

**시나리오: 당일 매출 정산**
1. `오늘` 탭을 선택합니다.
2. `대기` 상태 탭에서 미결제 건을 확인합니다.
3. 결제 금액과 방법(카드/현금/계좌이체)을 입력하고 확인합니다.
4. 하루 마감 시 CSV를 내보내 정산합니다.

#### 연관 섹션
- **운영현황** → 시술 완료 시 결제 건 자동 생성
- **리포트** → 월간 매출 데이터 원천
- **설정 > 기본정보** → 월 목표매출 설정

### 3.8 이벤트관리 (Events)

**경로**: `/admin/events`
**역할**: 홈페이지 프로모션/이벤트 관리

#### 주요 기능

| 기능 | 설명 |
|------|------|
| **이벤트 목록** | 검색 가능한 이벤트 카드 리스트 |
| **상태 배지** | 진행중(Active) / 종료(Ended) / 초안(Draft) |
| **이벤트 생성** | 제목(한/영), 기간, 카테고리, 포스터 이미지, 내용, 게시 여부 |
| **복제** | 기존 이벤트를 복제하여 새 이벤트 생성 |
| **편집/삭제** | 확인 다이얼로그 후 삭제 |
| **다국어 지원** | 한국어/영어 제목 및 내용 |
| **주요(Featured)** | 홈페이지 메인에 노출되는 주요 이벤트 지정 |

#### 사용 시나리오

**시나리오: 신규 이벤트 등록**
1. `새 이벤트` 버튼을 클릭합니다.
2. 한국어/영어 제목을 입력합니다.
3. 시작일/종료일을 설정합니다.
4. 카테고리를 선택합니다.
5. 포스터 이미지를 업로드합니다.
6. 내용을 작성합니다.
7. `게시` 체크박스를 활성화하고 저장합니다.
8. 홈페이지에 즉시 반영됩니다.

#### 연관 섹션
- **대시보드** → 활성 이벤트 수 KPI
- **홈페이지** → `/promotion` 페이지에 이벤트 표시
- **팝업관리** → 이벤트 홍보용 팝업 연동 가능

## 5. 역할별 사용 가이드

### 5.1 원장/실장 (경영진)
**주요 사용 메뉴**: 대시보드, 리포트, 매출관리, 설정
- 매일: 대시보드에서 병원 전체 현황 확인
- 매월: 리포트에서 경영 성과 분석, 전월 비교
- 수시: 매출관리에서 매출 추이 확인
- 설정: 목표 매출, 시술 가격, 직원 관리

### 5.2 접수/상담 직원
**주요 사용 메뉴**: 상담관리, 대시보드, 이벤트관리
- 매일: 대시보드 → 오늘 콜백 확인 → 상담관리에서 순서대로 처리
- 신규 상담 접수 시: 상담관리에서 등록 및 배정
- 이벤트: 진행 중 이벤트 확인 후 상담 시 안내

### 5.3 간호사/의료진
**주요 사용 메뉴**: 운영현황, 재고관리, 알림관리
- 매일: 운영현황에서 당일 시술 일정 확인
- 시술 전: 재고관리에서 사용 재료 등록
- 시술 후: 운영현황에서 완료 처리
- 주기적: 알림관리에서 팔로업 처리

### 5.4 시스템 관리자
**주요 사용 메뉴**: 설정 전체, 감사 로그
- 시술 항목/가격 변경: 설정 > 시술 마스터
- 직원 입퇴사: 설정 > 직원 관리
- 감사: 설정 > 감사 로그에서 활동 이력 확인
- 병원 정보 변경: 설정 > 기본정보

## 7. 섹션 간 통합 활용 시나리오

### 7.1 환자 전체 여정 (End-to-End)
```
홈페이지 상담 접수 → [상담관리] 신규 등록
→ 상담사 배정/콜백 → [상담관리] 상태 변경
→ 예약 확정 → [상담관리] 예약완료
→ 내원/시술 → [운영현황] 케이스 등록/진행
→ 재료 사용 → [재고관리] 사용 등록
→ 시술 완료 → [운영현황] 완료, [매출관리] 결제 처리
→ 팔로업 → [알림관리] 3일/7일 후 알림 발송
→ 경영 분석 → [리포트] 월간 통계 반영
```

### 7.2 이벤트 캠페인 관리
```
이벤트 기획 → [이벤트관리] 이벤트 등록 (포스터, 기간 설정)
→ 홍보 팝업 → [팝업관리] 팝업 등록 (이벤트 링크 연결)
→ 상담 유입 → [상담관리] 이벤트 통한 상담 추적
→ 시술 연결 → [운영현황] 이벤트 시술 진행
→ 매출 확인 → [매출관리] 이벤트 기간 매출
→ 성과 분석 → [리포트] 이벤트 전후 비교
```

### 7.3 재고-시술 연동 관리
```
시술 마스터 등록 → [설정] 시술 정보 + 카테고리
→ 레시피 설정 → [재고관리] 시술별 기본 사용 재료
→ 시술 진행 → [운영현황] 케이스 시작
→ 재고 차감 → [재고관리] 레시피 기반 자동 차감
→ 재고 부족 → [재고관리] 알림 배너 → [대시보드] 경고
→ 발주/입고 → [재고관리] 입고 처리
```

## 9. 기술 아키텍처

### 인증 흐름
```
브라우저 → /admin/login → Supabase Auth (이메일/비밀번호)
→ 세션 쿠키 발급 → (authenticated) layout에서 세션 검증
→ API 호출 시: createServerClient()로 인증 확인
→ DB 작업 시: createAdminClient()로 서비스 역할 접근 (RLS 우회)
```

### 데이터 흐름
```
클라이언트 (React) → API Route (Next.js) → Supabase (PostgreSQL)
                                         → Supabase RPC (재고 함수)
```
