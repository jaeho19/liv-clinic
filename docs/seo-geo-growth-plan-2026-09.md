# LIV 성형외과 SEO·GEO 후속 실행 계획서

작성일: 2026-09-09 · 기준 사이트: https://liv-clinic.net · 계획 기간: 착수일부터 12주

**목표는 검색 수집·색인, 비브랜드 검색 유입, 정확한 AI 출처 인용, 유효 상담으로 이어지는 흐름을 개선하고 실제 성과를 확인하는 것이다.** 기존 기술 개선을 다시 수행하는 계획이 아니라, 배포 후 남은 측정 공백과 사이트 전체의 개선 후보를 다룬다. 상위 노출과 AI 인용은 검색·AI 서비스가 결정하므로 확보를 보장하지 않는다. 우리가 통제할 수 있는 작업의 완료와 외부에서 관측한 성과를 별도로 판정한다.

이번 산출물은 실행 계획서다. 계획 작성 과정에서는 기존 보고서·소스와 운영 공개 페이지를 읽었으며, 사이트 코드·운영 설정·가격·DB를 변경하지 않았다.

## 1. 권장 순서와 운영 원칙

첫 2주는 **측정 계정과 실제 색인 상태, 모바일 속도**를 우선한다. 다음 4주는 **이미 있는 주요 페이지와 가이드의 내용·근거·연결**을 보강한다. 이후에는 **지역 검색·외부 출처·AI 인용 데이터**를 함께 보면서 효과가 확인된 주제에 작업을 집중한다.

- 기존 병원 정보는 사용자가 맞다고 확인한 내용을 기준으로 유지한다. 정보 전체를 다시 확인받는 절차를 착수 조건으로 만들지 않는다. 다른 표현·수치를 임의로 통일하지 않는다.
- **모든 가격 노출 지점의 금액·VAT·판매 옵션·샷/라인 수·할인·결제 및 관련 안내는 동결한다.** 가격 페이지, 시술 상세, 가이드, 이벤트 이미지까지 적용한다. 새 가격 원본과 별도 변경 요청이 오기 전에는 가격 내용·안내 문구를 편집하지 않는다.
- 기존 11개 언어를 유지한다. 집중 개선은 한국어·영어·일본어·번체 중국어를 기본안으로 하되, 첫 주의 국가·언어별 실제 수요로 순서를 조정한다. 간체 중국어 등 나머지 언어를 삭제하거나 일괄 noindex하지 않는다.
- 모바일 영상 유지라는 기존 선호를 반영한다. 우선 포스터 노출·다운로드·로딩 순서를 개선하고, 영상 제거·전면 리뉴얼을 기본안으로 삼지 않는다.
- 새 의학적 설명·새 사례·새 자격이나 인증을 추가할 때만 해당 근거와 실제 검토자를 확인한다. 검토 전 문장과 이미 승인된 기존 사실을 구분한다.
- 실제 상담 제출·채팅 시작·메일·문자·운영 DB 쓰기는 검증에 사용하지 않는다. 분석·폼 회귀는 모의 응답과 별도 테스트 환경에서 확인한다. 외부 프로필 수정과 환자 대상 연락은 운영 담당 업무로 분리한다.
- 모든 npm 명령은 `D:\dev\LIV_homepage\liv-clinic`에서 실행한다. 검증 코드와 원본 증빙은 상위 작업 폴더에 둔다. 기존 사용자 파일·비밀정보를 보존한다.

## 3. 최신 검색·AI 지침을 반영한 의사결정

### 3.1 Google의 AI 참여 설정과 성과 보고서 확인

Google은 Search Console에 **Search generative AI** 설정을 제공하며, 공식 문서에는 2026-08-31 전 세계 배포 완료가 명시돼 있다. 기본값은 포함이며, 하위 속성은 상위 속성 설정을 상속할 수 있다. `https://liv-clinic.net/`과 관련 상위 속성의 실제 적용값을 읽고, 의도하지 않은 제외가 있는지 확인한다. 현재 LIV의 설정값은 미확인이다. 학습 허용 여부와 이 검색 노출 설정은 별개다. [Google 공식 설정 안내](https://support.google.com/webmasters/answer/16908024)

생성형 AI 성과 보고서에서는 AI Overviews·AI Mode의 **노출**을 URL·국가·기기·날짜별로 확인한다. 보고서가 보이지 않으면 실제 설정, 데이터 부족, 계정 제공 상태를 기록하며 0회로 단정하지 않는다. CSV의 0에는 화면의 미제공 값이 변환된 경우도 있으므로 원래 화면 상태를 함께 보관한다. 이 지표는 일반 검색 실적의 Web 범위와 겹치므로 전체 노출에 다시 더하지 않는다. [Google 생성형 AI 성과 보고서](https://support.google.com/webmasters/answer/16984139?hl=en)

### 3.2 ChatGPT·Perplexity의 접근과 실제 인용을 구분

OpenAI 공식 문서는 검색용 `OAI-SearchBot`과 학습용 `GPTBot`을 구분한다. 검색 봇의 robots 허용과 공식 IP 요청 통과 여부를 점검한다. 기존 학습 봇 정책을 바꾸거나 학습 허용을 인용의 필수 조건으로 취급하지 않는다. [OpenAI 공식 크롤러 문서](https://developers.openai.com/api/docs/bots)

Perplexity도 검색용 봇과 사용자 요청용 접근을 구분한다. 방화벽 예외가 필요하다면 공식 IP와 User-Agent를 함께 검증해 공개 콘텐츠에 한정한다. 과거 User-Agent만 바꾼 200 응답은 실제 봇 IP 통과의 증명이 아니다. [Perplexity 공식 크롤러 문서](https://docs.perplexity.ai/docs/resources/perplexity-crawlers)

### 3.3 Bing 인용 데이터 활용

Bing Webmaster Tools의 AI Performance에서 인용 수·인용 URL·grounding query를 확인한다. 실제 화면에 제공되면 Intents·Topics·Citation Share·기간 비교도 활용한다. Bing의 Citation Share는 해당 검색 구절에서 관측된 출처 비중이며, 경쟁 사이트 순위·트래픽 점유율 또는 ChatGPT 전체 성과가 아니다. [AI Performance 기본 안내](https://blogs.bing.com/webmaster/February-2026/Introducing-AI-Performance-in-Bing-Webmaster-Tools-Public-Preview), [2026년 6월 확장 지표](https://blogs.bing.com/search/June-2026/New-AI-Visibility-Insights-in-Bing-Webmaster-Tools-Intents-Topics-Citation-Share-Compare)

### 3.4 효과를 기대할 근거가 있는 작업에 집중

환자가 실제로 궁금해하는 설명, 검토 가능한 출처, 내부 연결, 사용 경험에 집중한다. Google은 특별한 AI용 schema·llms.txt·문장 분할 규격을 요구하지 않는다. FAQ와 비교표는 이해를 돕기 위해 사용하며, 개수나 글자 수를 GEO 합격 기준으로 삼지 않는다. [Google 생성형 AI 최적화 가이드](https://developers.google.com/search/docs/fundamentals/ai-optimization-guide)

Google FAQ 리치 결과는 2026-05-07부터 표시가 종료됐다. 기존 FAQ 본문과 올바른 schema는 유지할 수 있지만, FAQ 리치 결과 획득을 이번 성과 목표에 넣지 않는다. [Google 공식 변경 이력](https://developers.google.com/search/updates)

DB 자격증명 폐기·교체 여부는 별도 운영 보안 항목 **S01**로 즉시 확인한다. 이미 교체됐다면 완료 일시·담당만 기록하고 비밀값을 수집하지 않는다. 미교체라면 계정 소유자가 교체와 연관 배포 비밀 설정 갱신을 수행한다. 이 항목을 병원 사실 확인이나 콘텐츠 검수와 합치지 않는다.

## 5. 첫 2주의 구체적 실행 방법

### 5.1 접근·색인·검색 수요 기준값

1. 계정에 이미 접근할 수 있으면 바로 읽는다. 접근이 없다면 해당 서비스·속성·필요한 권한만 기록한다. 일반 분석에는 읽기 권한을 우선하고 설정 변경에는 필요한 권한을 구분한다.
2. GSC에서 최근 완료된 28일과 그 이전 28일, 추세 확인용 90일 데이터를 확보한다. 페이지·검색어·국가·기기별로 분리하고 브랜드 검색과 비브랜드 검색을 나눈다. 검색어가 비공개 처리된 데이터는 분류 불명으로 남긴다.
3. 우선 20 URL을 URL 검사로 확인한다. 실제 색인 여부, 최근 수집 시각, 선언 canonical과 Google 선택 canonical, 차단·중복·발견/수집 후 미색인 이유를 기록한다.
4. 네이버와 Bing의 수집·색인·사이트맵 처리 결과도 따로 기록한다. 네이버 웹검색과 스마트플레이스 노출을 같은 지표로 합치지 않는다. [네이버 공식 웹마스터 가이드](https://searchadvisor.naver.com/guide/seo-basic-intro)
5. 과거 GSC 404 목록은 최신 내보내기로 다시 확인한다. 실제 후속 페이지가 있을 때만 301로 연결하며, 모든 404를 홈페이지로 보내지 않는다. 정상적으로 없어진 URL은 정상 404/410일 수 있다.
6. 색인 요청은 중요한 변경 URL에 제한한다. sitemap 제출·IndexNow 수신 성공과 실제 색인을 별도 칸에 기록한다. 반복 요청으로 순위나 색인을 확보한다고 간주하지 않는다. [Google 재수집 요청 안내](https://developers.google.com/search/docs/crawling-indexing/ask-google-to-recrawl), [IndexNow 공식 FAQ](https://www.indexnow.org/faq)

색인 분모는 현재 sitemap의 공개 대상 594개에서 출발한다. 이후 정당한 통합·비공개 변경이 있으면 분모 변경 이유를 남긴다. HTTP 200인 비공개 페이지와 검색엔진이 선택한 정상 중복 URL까지 모두 색인시키는 목표를 세우지 않는다.

### 5.2 실제 상위 노출 기회를 고르는 방법

- 후보 검색어는 GSC의 실제 노출·클릭, 네이버/Bing 실적, 공개 검색 결과의 문서 유형으로 선정한다. 현재 계획의 예시 검색어에 검색량이나 현재 순위를 부여하지 않는다.
- 우선 후보는 관련성이 높고 이미 노출이 발생하지만 클릭이 적은 검색어, 또는 개선 가능한 순위 구간에 있는 검색어다. GSC 평균 위치와 고정 조건의 실제 검색 순위를 구분한다.
- 4개 집중 언어에서 최대 10개씩, 총 40개 비브랜드 검색어를 후보 목록으로 만든다. 국가·언어·기기·지역 조건을 고정하고, 광고·지도·웹문서·AI 영역을 구분해 관측한다.
- 시장별 3~5개 비교 사이트는 해당 검색 결과에서 직접 선정한다. 원문 내용·출처·의료진 설명·지역 정보·답변 충실도·로딩을 비교한다. 대형 포털과 개별 병원의 역할 차이도 기록한다.
- 하나의 검색 목적에는 기존 대표 URL을 먼저 연결한다. 같은 시술명에 지역명만 바꾼 새 페이지를 대량 생성하지 않는다.

### 5.3 속도와 분석의 실제 원인 확인

**속도 표본:** ko/en 홈, ko 울쎄라, ko 가격, en 비교 가이드, ko 전후사진의 6개 유형. 모바일·데스크톱 각각 동일 기기/네트워크 조건으로 3회 측정해 중앙값을 비교한다. 서버 첫 응답·영상/포스터·큰 이미지·스크립트·폰트·지도/채팅 로딩 비용을 나눠 본다.

우선 조사할 것은 영상 로드 전에 보이는 포스터, 영상 첫 프레임 대기, 화면 아래 자산의 불필요한 초기 다운로드다. 이미 압축·최적화된 자산은 재측정 근거 없이 다시 작업하지 않는다. 영상은 유지하면서 동일한 첫 화면을 더 일찍 보여 주는 방법부터 검토한다. 9월 6일의 프록시 LCP 14.6초를 현재 속도나 개선율 계산의 기준값으로 쓰지 않는다.

실사용 목표는 모바일·데스크톱 75백분위에서 **LCP ≤ 2.5초, INP ≤ 200ms, CLS ≤ 0.1**이다. 실험실 TBT를 INP로 대체하거나 Lighthouse 점수를 검색 순위 점수로 해석하지 않는다. CrUX 데이터가 없으면 데이터 부족으로 표시하고, 필요성이 확인되면 개인정보를 담지 않는 실사용 성능 측정을 설계한다. [Web Vitals 공식 기준](https://web.dev/articles/vitals)

**분석 표본:** 첫 진입, 언어 변경, SPA 이동, 늦게 도착한 분석 스크립트, 새로고침, 뒤로 이동, 폼 성공/실패의 모의 응답. 현재 코드에 있는 `generate_lead`, `contact`, `cta_click`, `language_switch`, 채팅 이벤트를 목록화한다. 태그가 늦게 로드될 때 이벤트 설치가 누락되는지, 라우트 이동 시 페이지뷰·스크롤·체류가 누락 또는 중복되는지 확인한다. 이는 소스에서 찾은 조사 후보이며 운영에서 확정한 오류가 아니다.

상담 버튼 클릭·전화 링크 클릭·메신저 열기는 **관심 행동**이다. 성공 응답에 따른 접수와 운영자가 확인한 유효 상담은 다른 지표다. 테스트 접수로 운영 수치를 만들지 않고 기존 집계 자료 또는 승인된 테스트 환경으로 검증한다. 이름·전화·이메일·상담 내용·건강정보를 분석 이벤트에 추가하지 않는다. UTM 첫 유입과 GA4의 기여 방식 차이도 명시한다.

IndexNow는 현재 `NODE_ENV` 기반 전송 조건을 쓰므로 preview 빌드에서도 발송될 수 있는 조건이 있는지 별도로 모의 테스트한다. 운영 알림을 실제 발생시키기 위해 이벤트·후기를 생성하지 않는다.

## 7. 지역 검색과 외부 출처

Google Business Profile, 네이버 스마트플레이스, Bing Places의 기존 관리 권한과 홈페이지 링크·카테고리·사진·영업 안내를 점검한다. 사이트의 승인된 정보를 기준으로 명백한 오류와 깨진 링크를 정리하되, 기존 별칭·언어별 이름·동선 설명의 차이를 자동으로 잘못된 정보로 판단하지 않는다. Google은 지역 결과에서 관련성·거리·인지도 등을 고려한다고 설명하므로, 사이트 코드만으로 지역 순위를 통제할 수는 없다. [Google 지역 검색 안내](https://support.google.com/business/answer/7091?hl=en)

과거 문서의 외부 플랫폼 `LV` 표기, 연결 오류 등은 **현재 공개 화면을 재확인할 후보**다. 계정 권한과 정확한 변경안을 준비해 운영자가 정정한다. 이미 해결된 항목이면 완료 처리하고 중복 작업하지 않는다.

기존 의료진 논문·정식 소개·실제 장비 공급사 또는 학회 프로필 등 관계가 입증된 출처에 적절한 홈페이지/의료진 링크가 있는지 확인한다. 새로운 자격·제휴·인증을 만들어내지 않는다. 실제 보유한 원본 사진·의료진 설명 영상이 있으면 동의·검토 범위 안에서 설명문과 관련 페이지를 연결한다. 링크 개수 자체를 성과로 삼지 않는다.

후기 운영은 실제 경험에 기반한 자발적 참여를 원칙으로 한다. 모든 의견을 받을 수 있는 안내를 사용하고, 혜택 제공·긍정 평가만 선별 요청·후기 대필을 목표 달성 수단으로 삼지 않는다. 답변에 환자의 진료 정보를 노출하지 않는다. 기존의 후기 관리 시스템을 활용하며 새 수집 시스템 도입을 기본 과제로 만들지 않는다. [Google 후기 정책과 운영 안내](https://support.google.com/business/answer/3474122)

배포일·콘텐츠 변경일·계절성·광고/이벤트 변화를 같이 기록한다. 최근 잠정 데이터와 완결 기간을 섞지 않고, 공식 데이터 장애 이력도 확인한다. 예를 들어 Google은 8월 13~17일 생성형 AI 노출 누락분을 8월 21일 복원했다고 공지했다. 오래된 내보내기를 기준으로 삼으면 다시 내려받아야 한다. [Search Console 데이터 이상 이력](https://support.google.com/webmasters/answer/6211453?hl=en)

### 8.1 AI 질문 실험 운영

- 부록의 20개 질문을 첫 주에 확정한다. 언어별 브랜드 질문 1개·비브랜드 질문 4개를 구분한다. 브랜드가 포함된 질문의 성공률을 자연 발견 성과에 합치지 않는다.
- ChatGPT 검색, Perplexity, Copilot에서 같은 질문을 **LIV 대화 이력·첨부·URL 힌트가 없는 새 세션**으로 실행한다. 서비스·검색 모드·표시 모델·국가/언어·일시를 기록한다. 실제 계정 접근이 없는 서비스는 미검증으로 남긴다.
- 기준 시점과 4·8·12주에 서로 다른 두 날 각각 20문항 × 3서비스를 관측한다. 정밀 회차당 최대 120개 응답이며, 그 사이에는 대표 5문항을 주 1회 확인한다.
- 정상 답변은 나왔지만 인용이 없으면 0으로 기록한다. 로그인 불가·기술 실패는 별도 실패 상태로 두고 분모에서 제외한다. 질문이 검색을 사용하지 않은 경우도 관측 조건을 기록한다.
- 직접 인용률 = 공식 도메인으로 최종 연결되는 출처가 하나 이상 있는 유효 응답 수 ÷ 유효 응답 수. 병원명만 언급, 외부 병원 소개 페이지 인용, 공식 사이트 직접 인용을 각각 집계한다.
- 출처 링크가 존재하는지만 보지 않고, 해당 문장이 실제 링크의 원문에서 뒷받침되는지 확인한다. 질문별 원문 응답·출처 URL·판정 근거를 저장한다.
- URL을 직접 제시해 요약을 요청하는 실험은 접근성 점검으로 따로 분류한다. API 실험을 소비자용 ChatGPT 화면의 성과로 대신 보고하지 않는다.
- Google AI Overviews/AI Mode는 공식 보고서를 주 지표로 사용하고, 공개 화면의 출현 여부는 보조 관측으로 기록한다. 해당 검색에서 AI 영역이 뜨지 않은 것을 사이트 장애로 보지 않는다.

## 10. 완료 판정과 유지 관리

각 항목은 **구현 완료 → 배포 검증 완료 → 실제 색인 확인 → 성과 관측**을 별도로 기록한다. 계획 종료 시 어떤 단계까지 확인됐는지 보여 주며, 배포 성공만으로 SEO·GEO 성과 완료라고 표시하지 않는다.

코드 변경은 관련 lint·type·test·build 검사를 통과시키고, 현재 운영의 canonical·robots·sitemap·다국어·가격 보존 검사를 유지한다. 인덱싱·배포 환경을 다루는 수정에는 SSR/ISR 이후 정책 유지와 preview의 noindex/빈 sitemap도 포함한다. 점검 규칙을 끄거나 테스트를 삭제해 통과시키지 않는다.

외부 계정 때문에 수행하지 못한 항목은 서비스명·필요한 권한·확인할 화면·담당자를 기재한다. 핵심 계정 검증이 미완료이면 해당 성과를 확인했다고 보고하지 않는다. 새 업무를 수행할 때도 이미 제공된 권한과 승인은 활용하고 통상적인 구현마다 확인을 반복하지 않는다.

매주: 주요 URL 상태, 검색 수집 오류, 분석 이상, 대표 AI 질문을 확인한다. 매월: 28일 추세, 우선 콘텐츠, 외부 프로필과 실제 운영 변경을 반영한다. 분기마다: 주제·언어별 투자 순서를 재평가한다. 검색 결과와 AI 응답의 변화는 통제할 수 없는 외부 요인을 포함하므로 변경 기록과 함께 해석한다.
