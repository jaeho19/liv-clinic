# Plan: 고객 관리 및 알림 시스템

> PDCA Phase: **Plan**
> Created: 2026-02-03
> Feature: customer-notification-system

---

## 1. 배경 및 문제 정의

### 현재 상황
- 보톡스 시술에 한해서만 3개월 후 재시술 문자 자동 발송 (베가스 차트 시스템)
- 문자 발송 비용 발생
- 카카오톡 사후관리 안내가 모든 환자에게 동일한 내용으로 일괄 발송
- 시술별 주기가 다름에도 통합 관리 시스템 부재

### 핵심 문제
1. **시술 주기 다양성 미대응**: 울쎄라(6개월), 스킨부스터(3개월), 보톡스(3개월) 등 시술마다 다른 주기를 관리하지 못함
2. **개인화 부재**: 환자별 시술 이력과 생활 습관을 고려한 맞춤형 안내 부재
3. **카카오톡 자동 연동 불가**: 차트 시스템과 카카오톡 채널 간 자동 발송 기능 미지원
4. **업무 누락 위험**: 수동 발송 시 담당자가 놓칠 가능성

## 2. 목표

### 주요 목표
- 어드민 대시보드에 **고객 알림 관리** 메뉴를 추가하여, 시술 주기 기반 재방문 알림을 **반자동**으로 관리
- 직원에게 발송 대상 목록을 자동으로 제시하고, 발송 완료를 체크하는 워크플로우 구축

### 구체적 목표
| # | 목표 | 측정 기준 |
|---|------|----------|
| G1 | 시술별 알림 주기 설정 | 시술 마스터에 주기(일) 필드 추가 |
| G2 | 환자 시술 이력 관리 | 시술 기록 테이블 생성 및 CRUD |
| G3 | 오늘 발송 대상 자동 산출 | 시술일 + 주기 = 오늘인 고객 목록 |
| G4 | 발송 워크플로우 (반자동) | 발송 대상 확인 → 발송 → 완료 체크 |
| G5 | 콘텐츠 템플릿 관리 | 시술별 사후관리 안내 템플릿 + 영상 링크 |
| G6 | 대시보드 KPI 추가 | 오늘 발송 대상 수, 미발송 건수 위젯 |

## 3. 범위 (Scope)

### In-Scope
1. **DB 스키마 확장**
   - `patient_treatments` 테이블 (환자 시술 이력)
   - `notification_queue` 테이블 (알림 대기열)
   - `notification_templates` 테이블 (시술별 알림 템플릿)
   - `treatment_masters` 테이블에 `notification_cycle_days` 필드 추가

2. **어드민 페이지 추가**
   - `/admin/notifications` - 알림 관리 메인
     - 오늘 발송 대상 목록 (자동 산출)
     - 발송 완료 체크
     - 미발송 건 강조
   - `/admin/notifications/templates` - 알림 템플릿 관리
     - 시술별 사후관리 안내 문구
     - 재방문 권유 문구
     - 영상 콘텐츠 URL 연결
   - `/admin/notifications/history` - 발송 이력

3. **환자 시술 기록 관리**
   - 시술 완료 시 기록 등록 (운영현황 연동 또는 수동 입력)
   - 환자별 시술 이력 조회

4. **대시보드 연동**
   - 오늘 발송 대상 수 KPI 카드
   - 미발송 건 알림 배너

5. **사이드바 메뉴 추가**
   - '병원 운영' 섹션에 '알림관리' 메뉴

### Out-of-Scope (향후 확장)
- 카카오톡 API 자동 발송 연동 (현재는 반자동)
- 문자 API 직접 연동
- 베가스 차트 시스템 직접 연동
- 푸시 알림 (웹/모바일)
- AI 기반 최적 발송 시점 추천

## 4. 기술 설계 개요

### 아키텍처
```
[운영현황/수동입력] → [patient_treatments] → [배치 계산]
                                                  ↓
[설정: 시술별 주기] → [notification_queue] ← [오늘 날짜 비교]
                                                  ↓
                     [어드민 대시보드] → 직원 확인 → [발송 완료 체크]
                                                  ↓
                     [notification_history] ← [발송 기록 저장]
```

### DB 스키마

#### patient_treatments (환자 시술 이력)
| Column | Type | Description |
|--------|------|-------------|
| id | uuid | PK |
| patient_name | text | 환자명 |
| phone | text | 전화번호 |
| treatment_name | text | 시술명 (시술 마스터 참조) |
| treatment_category | text | 카테고리 |
| doctor | text | 담당의 |
| treated_at | timestamptz | 시술일 |
| next_notification_at | timestamptz | 다음 알림일 (시술일 + 주기) |
| notification_sent | boolean | 알림 발송 여부 |
| notes | text | 메모 |
| created_at | timestamptz | 등록일 |

#### notification_templates (알림 템플릿)
| Column | Type | Description |
|--------|------|-------------|
| id | uuid | PK |
| treatment_name | text | 시술명 |
| template_type | text | 'aftercare' / 'revisit' |
| title | text | 템플릿 제목 |
| message | text | 메시지 본문 |
| video_url | text? | 영상 콘텐츠 URL |
| is_active | boolean | 활성 여부 |
| created_at | timestamptz | 생성일 |
| updated_at | timestamptz | 수정일 |

#### notification_history (발송 이력)
| Column | Type | Description |
|--------|------|-------------|
| id | uuid | PK |
| patient_treatment_id | uuid | FK → patient_treatments |
| template_id | uuid? | FK → notification_templates |
| channel | text | 'kakao' / 'sms' / 'call' |
| sent_by | text | 발송 담당자 |
| sent_at | timestamptz | 발송 시각 |
| status | text | 'sent' / 'failed' / 'skipped' |
| notes | text? | 메모 |

### 시술별 알림 주기 기본값
| 시술 | 주기 | 비고 |
|------|------|------|
| 보톡스 | 90일 (3개월) | 효과 지속 3~6개월 |
| 필러 | 365일 (12개월) | 종류별 상이 |
| 스킨부스터 | 90일 (3개월) | 정기 관리 |
| 울쎄라 | 180일 (6개월) | 연 1~2회 |
| 써마지 | 180일 (6개월) | 연 1~2회 |
| 덴서티 | 90일 (3개월) | 3회 1세트 |
| 인모드 | 30일 (1개월) | 월 1회 유지 |
| 슈링크 | 90일 (3개월) | 3~6개월 |
| 실리프팅 | 365일 (12개월) | 연 1회 |

## 5. 구현 순서

### Phase 1: DB & 타입 정의
1. Supabase에 `patient_treatments`, `notification_templates`, `notification_history` 테이블 생성
2. TypeScript 타입 정의 (`src/types/admin.ts` 확장)
3. 시술 마스터에 `notification_cycle_days` 필드 추가

### Phase 2: API 엔드포인트
1. `GET/POST /api/admin/patient-treatments` - 시술 이력 CRUD
2. `GET /api/admin/notifications/today` - 오늘 발송 대상 산출
3. `POST /api/admin/notifications/complete` - 발송 완료 처리
4. `GET/POST/PATCH/DELETE /api/admin/notification-templates` - 템플릿 CRUD
5. `GET /api/admin/notifications/history` - 발송 이력 조회

### Phase 3: 어드민 UI
1. 사이드바에 '알림관리' 메뉴 추가
2. `/admin/notifications` 메인 페이지 (오늘 발송 대상 목록)
3. `/admin/notifications/templates` 템플릿 관리 페이지
4. `/admin/notifications/history` 발송 이력 페이지

### Phase 4: 대시보드 연동
1. 대시보드에 '오늘 발송 대상' KPI 카드 추가
2. 미발송 건 알림 배너 추가

### Phase 5: 시술 기록 연동
1. 운영현황 '완료' 시 자동 시술 기록 생성 (선택적)
2. 수동 시술 기록 입력 폼
