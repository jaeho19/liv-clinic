## 2. 기존 ②편에서 가져올 것 — 내용은 이미 정리돼 있다

기존 **②편 〈실이 하는 일〉 240초**가 압토스 영상이었고, 그 **내용 구성은 사장님 검토를 거친 것**이다:

> A 훅(실은 당기지 않습니다/겁니다) → B 실물(P01) → C 실 메커니즘 3단계 → D NAMICA 캡슐 확산
> → E 라인업·적용 부위 → F 인증 4종·100개국 → G 본사 연수·수료·KR0062025 → H 공간 → I QR

**이 내용 뼈대는 다시 설계할 필요가 없다.** 사실관계·금지 문구 검토·원장님 확인이 끝난 상태다.
6분으로 늘리면서 각 블록에 숨 쉴 공간을 주고, **연출과 조판을 완전히 새로 짜는 것**이 이번 작업이다.

`output/lobby-monitor/edit/video_thread.py`를 읽으면 각 블록이 어떤 에셋을 어떤 타이밍에 쓰는지
전부 나와 있다. **내용 참고용으로 읽되, 레이아웃은 따라 하지 마라.**

## 3. 레퍼런스 분석 — 「세련됨」의 정체

주신 두 링크를 읽었다. 무엇을 가져오고 무엇을 **절대 가져오면 안 되는지** 나눠 적는다.

### 가져올 것 — 이게 세련돼 보이는 이유다

| 레퍼런스가 하는 것 | 현재 우리 영상 | 적용 방법 |
| --- | --- | --- |
| **영문 섹션 마커 + 한글 본문** (`WHAT IS IT?` `BIO LIFTING` `RECOMMEND`) | 한글만, 전부 같은 무게 | 작은 영문 키커(자간 넓게) **위**에 큰 한글 헤드라인. 이 하나가 체감 차이의 절반이다 |
| **번호 매긴 섹션** (`1.` `2.` … / `POINT 1~5`) | 번호 없음 | `01 / 02 / 03` 큰 숫자를 섹션 오프너에 |
| **정보를 담은 표·비교** | 카드가 장식용 | 라인업·적용 부위를 **표**로. 카드 테두리 말고 괘선으로 |
| **넉넉한 여백, 좌측 정렬** | 전부 중앙 정렬 | 그리드를 세우고 좌측 정렬 블록을 섞어라 |
| **원리 도해가 독립 비주얼** | 카드 안에 작게 | 이미 `thread_anim`이 있다. **화면을 채워라** |

### 현재 영상이 투박해 보이는 구체적 원인 (내가 스틸을 보고 판단한 것)

1. **모든 것이 중앙 정렬이다.** 제목·사진·자막이 예외 없이 가운데. 편집 디자인이 아니라 발표 슬라이드로 보인다.
2. **둥근 모서리 카드 + 드롭섀도.** 2010년대 앱 UI 문법이다. 에디토리얼은 하드 엣지와 괘선을 쓴다.
3. **그리드가 없다.** 요소가 손으로 찍은 y 좌표에 떠 있다.
4. **전환이 크로스디졸브 하나뿐이다.** 설계서가 "하드컷·와이프·마스크 혼용"을 요구했는데 16분 통틀어 마스크 전환이 **1회**다.
5. **톤 폭이 좁다.** 로즈~브라운 중간톤만 있고 **진짜 어두운 톤이 없어** 대비 punch가 안 산다.
6. **타이포 스케일 대비가 약하다.** 54~116px 안에서만 논다. 섹션 오프너는 140~180px까지 가야 한다.

### 절대 가져오면 안 되는 것 — **레퍼런스 문구는 우리 기준에 걸린다**

톡스앤필·세예 페이지에는 리브 설계서 §4가 **명시적으로 금지한 표현이 그대로 들어 있다.**
보고 베끼면 그대로 위반이다.

| 레퍼런스 문구 | 왜 안 되나 |
| --- | --- |
| "**4세대** 압토스 실" | 설계서 §4 금지 — 우월성 표현. `copy_guard`가 잡는다 |
| "최대 **2년**까지 효과 유지", "18~24개월에 걸쳐 분해" | 설계서 §4 금지 — 효과 기간 확약 |
| "천 건 이상의 시술", "**실제 후기**", 환자 사례 2건 | 설계서 §4 금지 — 환자 후기·체험담 |
| "압토스 **vs** 강남의 다른 인기 시술" 비교표 | 설계서 §4 금지 — 타 병원 비교 |
| 전후 사진 | 설계서 §4 금지 |
| "90개국 이상" | 리브가 확인한 값은 **"100개국 이상 사용"**이다. 남의 숫자를 쓰지 마라 |

**우리가 그대로 써도 되는 사실** (설계서가 확인): KFDA 의료기기 4등급 정식 허가 · CE · ISO 13485 ·
FDA MDSAP · 100개국 이상 사용 · 히알루론산을 나노/서브마이크로/마이크로로 캡슐화하는 구조 ·
APTOS Professional Course 수료 `KR0062025` · 라인업 3종과 적용 부위.

> 새 세션에서 대본을 쓰면 **반드시 `python output/lobby-monitor/edit/copy_guard.py`로 검사**해라.
> 검사 파일 목록에 새 모듈을 추가하는 것도 잊지 마라.

## 4. 이미지로 만들 것 / 영상으로 만들 것 / 코드로 그릴 것

사장님이 "어떤 부분을 이미지로, 어떤 부분을 영상으로" 정해 달라고 하셨다. **세 갈래**로 나뉜다.

### ① Higgsfield **영상**(kling3_0, 10.5크레딧/6초) — 최소한만

움직임이 **반드시 살아 있어야 하는 배경**에만 쓴다. 6분이면 배경 구간이 10개 이상 필요한데
전부 영상으로 만들면 100크레딧을 넘긴다.

- 섹션 오프너 배경 3~4개 (빛이 흐르거나 입자가 떠다니는 추상)
- 마무리 배경 1개

⚠️ 실측된 함정: **9:16을 요청해도 1076×1928 / 24fps / 145프레임으로 나온다.** 변환 명령은
`output/lobby-monitor/generation_log.json`의 `pipeline.frame_conversion`에 있다. `minterpolate`가
마지막 프레임을 버려 179장이 되므로 복제로 180을 채운다. `declined_preset_id`를 안 보내면
프롬프트 단어 때문에 **프리셋 추천으로 대체되어 job이 조용히 안 만들어진다.**

### ② Higgsfield **이미지**(nano_banana_pro, 2크레딧) — 배경 대부분

**영상보다 5배 싸다.** 정지 이미지를 받아 렌더러에서 켄번즈로 밀면 6분 내내 움직임이 유지된다.
이전 작업에서 검증된 방식이고, 실제로 배경의 대부분이 이렇게 동작했다.

- 섹션별 배경 플레이트 8~12장
- 질감(트래버틴·월넛·천) 클로즈업

⚠️ **켄번즈 속도는 `KB_RATE = 0.009` 이상이어야 한다.** 0.0034에서는 `freezedetect`가 4건 걸렸다.
H06처럼 거의 정지인 클립은 감광까지 걸면 정지 구간이 된다 — **라이브 구간에도 푸시인을 걸어라.**

### ③ **코드로 그릴 것** — 의료 내용은 전부 여기

AI에 맡기면 안 되는 것들이다. 이미 모듈이 있다.

- **실 메커니즘 3단계** → `thread_anim.py` (삽입·걸림·고정). 6분에서는 **화면을 채워 크게**
- **NAMICA 캡슐 확산** → `particle_anim.py`
- **얼굴 부위 표시** → `face_diagram.py` (브래킷 방식)
- **조판 전부** — 영문 키커·한글 헤드라인·번호·표·인증 블록
- 개념도 구간에는 **"개념도" 표기 필수**(실촬영 오인 방지)

### ④ **실사 그대로** — 증거는 사진이어야 한다

P01/P01T(제품·실 매크로), A01(인증서), A02(수여식), A09/A10(학회·연단), A11(상담), I01~I07(공간).
**원본의 인물·제품 형태를 변형하지 마라. 확대·이동·크롭만 허용.**

## 7. 이전 작업에서 피 흘려 배운 것 — 반복하지 마라

1. **cp949 함정**: 이 PC의 python stdout 기본 인코딩이 cp949다. 리디렉션된 `print`에 `✓`·이모지·em dash가
   하나라도 있으면 `UnicodeEncodeError`로 청크 렌더가 죽는다. **청크 렌더 명령에 `PYTHONIOENCODING=utf-8`**.
2. **캐시된 PIL 이미지를 제자리 변형하면 안 된다.** `@lru_cache`가 가변 이미지를 돌려주고 호출부가
   그 위에 그리면, 같은 인덱스 재요청 시 덧그려진다. 실제로 **97프레임 스트로브**가 출고본에 들어갔었다.
   `freezedetect`·`blackdetect`는 이걸 **원리상 못 잡는다**(움직임이 넘치는 방향이라). 멱등성 테스트가 있다.
3. **결함이 결함을 가린다.** 위 스트로브가 그 아래 있던 3.167초 freeze를 가리고 있었다. **지표가 0이라고
   해서 안전한 게 아니다.**
4. **`fit_size`는 조용히 줄인다.** 72px로 지정해도 `maxw`를 넘으면 60px로 렌더된다. 두 번 터졌다.
5. **병렬 커밋**: `git add` + pathspec 없는 `git commit`을 쓰면 **다른 에이전트가 스테이징한 파일이 섞인다.**
   반드시 `git add <경로>` 뒤 `git commit -F <파일> -- <경로>`.
6. **서브에이전트 모델**: 2026-09-19 마지막 작업에서 `opus` 서브에이전트가
   `oauth_org_not_allowed`(HTTP 403, "organization has disabled Claude subscription access for Claude Code")로
   중단됐다. **새 세션에서 서브에이전트를 쓸 거면 먼저 작은 작업으로 모델이 뜨는지 확인해라.**

## 8. 새 세션 시작하는 법

붙여넣을 프롬프트는 **`output/aptos-6min/NEW_CHAT_PROMPT.txt`** 에 따로 있다. 그대로 복사해 쓰면 된다.

### 이번에 반드시 다르게 할 것 — 디자인 먼저 승인

이전 작업은 **기술적으로는 성공하고 디자인에서 실패했다.** 119개 테스트를 통과하고 규격 오차 0에
금지 문구 0건이었는데, 완성본이 기준에 못 미쳐 쓰이지 않게 됐다. 원인은 과정에 있다 —
**6분을 다 만든 뒤에야 눈으로 볼 수 있었다.**

그러니 순서를 바꿔라:

1. **룩 개발을 먼저.** 대표 장면 3~4개를 **정지 이미지로** 만들어 사장님께 보여주고 승인받는다.
   섹션 오프너 1장, 개념도 1장, 실사 블록 1장, 마무리 1장이면 판단이 된다.
2. **승인된 룩으로 30초 파일럿**을 만들어 다시 확인받는다. 움직임과 전환은 정지 이미지로 판단할 수 없다.
3. **그 다음에 6분 전체.** 여기서부터는 이전 작업의 검수 체계(테스트·qc_check)를 그대로 쓴다.

1·2단계를 건너뛰면 같은 일이 반복된다. **6분을 만든 뒤에 "투박하다"는 말을 들으면 되돌릴 수가 없다.**
