## 2. 타이포 3종

| 역할 | 얼굴 | 크기 |
| --- | --- | --- |
| 섹션 번호 · 영문 키커 | **Cormorant Garamond** (홈페이지 `--font-serif`) | 30 / 150~180 |
| 한글 헤드라인 | **Paperlogy** (홈페이지 `--font-sans`) | 64~116 |

홈페이지와 같은 얼굴을 쓴다. 이전 영상은 Pretendard 한 종류였다.

> 증빙 번호(`KR0062025`)만 세리프를 안 쓴다. Cormorant 의 기본 숫자는 올드스타일이라
> 0 과 6 의 높이가 달라 공식 번호가 날짜처럼 읽힌다(실측). 산세리프 + 넓은 자간으로 뒀다.

## 3. 필드 — 화면은 항상 셋 중 하나

- **NOIR** 먹 필드: 개념도·오프너·증거
- **PAPER** 지면 필드: 표·데이터 (크롬이 먹색 변형으로 바뀐다)
- **PHOTO** 사진 전면: 하드 엣지, 테두리 없음

섹션마다 번갈아 써서 톤 폭을 만든다. 이전 영상은 전부 로즈~브라운 중간톤이었다.

## 4. 고정 크롬도 바꿨다

필 모양 로즈 버튼 + 그라디언트 스크림을 버리고 **괘선 + 로즈 마커**로 짰다.
밝은 필드용 먹색 변형이 따로 있다(`chrome(img, "paper")`).

## 5. 개념도는 다시 그렸다

이전 `thread_anim` 은 가로줄 9개 위 흰 곡선 하나였다. 바꾼 것:

- **배율** — 돌기 14개(46px) → **7개(118px)**. 무엇이 일어나는지 화면에서 보여야 도해다
- **조직** — 균일한 가로줄 → **층으로 눕힌 섬유 다발**, 위아래는 페더로 녹인다
- **돌기** — 좌우로 방향이 갈리는 원뿔형. 누웠다가 선다
- **2배 수퍼샘플링** — PIL 선에는 안티에일리어싱이 없다

## 피 흘려 배운 것 — 반복하지 마라

1. **Topaz 얼굴 보정(`face_enhancement`)은 실제 인물의 얼굴을 다시 그린다.**
   원장님 이목구비와 표정이 원본과 달라진다(`gen/_cmp_face_zoom.jpg` 에 대조 있음).
   인증·연수 사진은 증거라서 형태가 바뀌면 안 된다. **항상 OFF.**
2. **업스케일은 작은 글자를 지어낸다.** 로비 간판 아래 영문이 엉뚱한 글자로 바뀌었다.
   그래서 **A01(인증서)은 일부러 업스케일하지 않았다** — 그 사진은 글자가 증거다.
3. **제품 박스를 크게 쓰면 안 된다.** 박스 옆면에
   `4th GENERATION THREADS WITH ENHANCED LIFETIME` 이 인쇄돼 있다.
   설계서 §4 가 금지한 "4세대"가 화면에서 읽히게 된다.
4. **생성한 제품 이미지는 "실물 사진"으로 표기하지 않는다.** S1 의 구분 표기를
   `제품 이미지` 로 바꿨다. 실촬영으로 오인시키면 안 된다.
5. 소스 업로드는 `media_upload` 의 presigned URL 대신 **`media_import_url`** 이 낫다 —
   에셋이 `https://liv-clinic.net/images/...` 에 원본 바이트 그대로 공개돼 있다.
6. `topaz_image` 의 `face_enhancement_strength` 는 **0.1 배수만** 받는다(422 에러).

> "나쁘지는 않지만 조금 AI가 만든 것 같다. 사진 프레임들을 연결한 것 같은 느낌."

맞는 지적이었고 원인은 숫자로 나온다. v1 의 프레임 간 변화량 **중앙값 0.111** —

# 라인업을 이미지로 (2026-09-21)

> "라인업과 적용 부위 같은 게 이미지로 제시되면 훨씬 더 좋을 것 같아.
>  그냥 텍스트면 별로 효과가 없을 것 같거든."

맞는 지적이다. `볼` `중안부 · 하안부` `이중턱` 은 글자로 읽는 것보다 얼굴 위에서
보는 쪽이 훨씬 빠르다. 레퍼런스(톡스앤필·세예)도 얼굴 사진에 지시선을 건다.

## 얼굴을 무엇으로 쓸 것인가 — 세 안을 만들어 봤다

| 안 | 결과 |
| --- | --- |
| F1 대리석 조각 흉상 | **채택.** 팔레트가 정확히 맞고 볼·중안부·턱 아래가 다 읽힌다 |
| F2 등고선 추상 | 강렬하지만 측면이라 볼을 짚기 어렵고 톤이 '기술' 쪽으로 기운다 |
| F3 세라믹 마네킹 | 깔끔하지만 이목구비가 너무 없고 색이 차갑다 |

**모델 얼굴이나 환자 사진은 쓰지 않는다.** 사람 얼굴을 쓰면 시술 사례로 오인될 수
있고, 설계서 §4 는 전후 사진과 환자 사례를 금지한다. 오인 여지 자체를 만들지 않는
쪽이 맞다. 조각은 팔레트가 이미 맞고, 부위 표시가 얹혀도 '사람'이 아니라 '도해'로
읽힌다. 화면 표기도 `개념도` 로 나간다.

## 구현 — `face_areas.py`

부위마다 **글로우 + 아주 느리게 맥동하는 링 + 앵커 점 + 왼쪽 기둥까지 잇는 지시선**.
링을 정지시키면 스티커로 보이고, 숨 쉬면 '표시'로 읽힌다.

세 부위를 순서대로 켜면서(볼 → 중안부·하안부 → 이중턱) 나머지는 26% 로 낮춘다.

## 여기서 잡은 버그

푸시인을 걸면 **부위 표시가 얼굴에서 미끄러진다.** 앵커는 줌 1.0 화면좌표인데
바탕만 줌이 걸려서 생긴 어긋남이다. `project(ax, ay, z)` 가 `cover()` 와 같은
크롭 계산을 앵커에도 적용해 해결했다. 반지름도 z 배로 같이 키운다.

> F1 원본(2160×3840)은 화면과 가로세로비가 정확히 같다. 그래서 **줌 1.0 에서는
> cx/cy 가 아무 효과도 없다.** 크롭 이동은 줌 > 1 에서만 생긴다 — 처음에 cx 를
> 바꿔 얼굴을 옆으로 밀려다 아무 일도 안 일어나서 한참 헤맸다.

# 3단계 — 6분 전체 (2026-09-21)

**파일**: `output/aptos-6min/aptos_6min.mp4` · 완성 보고는 `DELIVERY.md`

사장님 결정: **섹션 안에서 강약** — 매 섹션을 클립으로 세게 열고 본문에서 내린다.

## 피 흘려 배운 것 — 반복하지 마라

### 1. 인계문의 움직임 숫자를 그대로 믿지 마라. 자가 다르다

인계문은 2단계 결과를 "전체 중앙값 0.478, v1 은 0.111" 로 적어 뒀다. 그 숫자로 목표를
잡았는데, **`verify_film.py` 로 같은 파일을 다시 재니 0.430 / 0.087 이 나왔다.** 같은
V1 클립을 쓴 A 구간도 인계문은 0.640, 이 코드로는 0.558 이다.

측정 해상도·보간 방식·전환 구간 제외 여부가 조금만 달라도 숫자가 10~20% 움직인다.
**기준선은 반드시 지금 쓰는 코드로 다시 재라.** 승인된 판과 폐기된 판이 둘 다 파일로
남아 있는 것이 이 프로젝트의 큰 자산이다.

같은 코드로 다시 잰 기준선:

    v2 (승인)  전체 0.430   블록 0.211 ~ 1.540   블록 중앙 0.395   강약 1.84배
    v1 (폐기)  전체 0.087   블록 0.031 ~ 0.129

### 2. 목표를 근거 없이 높게 잡으면 스스로를 막는다

처음에 클립 자체의 움직임(V4 는 5.106)을 보고 "악센트 1.0" 으로 잡았다. 그런데 최종
렌더는 고정 크롬·스크림·조판이 정지 영역이라 클립 원본의 **0.37~0.5배**로 희석된다.
승인된 판의 악센트 하단이 0.273 인데 1.0 을 요구한 것이다 — **승인된 판보다 엄격한
기준**이었고, 그 기준으로는 무엇을 해도 통과하지 못한다.

강약비도 같았다. 2.0 배를 요구했는데 승인된 판 자신이 1.84 배였다.

### 3. 움직임 지표는 **빈 어두운 면**에 지배당한다

실 매크로처럼 근사 흑 위에 가는 선 하나가 있는 그림은, 선이 아무리 활발해도 화면
평균 변화량이 낮게 나온다(공간 기울기 × 이동량이라서). 승인된 v2 의 돌기 구간도
0.273 이었다. **숫자가 낮다고 죽은 화면인 것은 아니다.** 그래서 블록별 하한은
승인판의 같은 성격 블록에서 가져오고, 진짜 판정은 분포(전체 중앙값·블록 최저·블록
중앙값)로 한다.

### 4. 매끈한 면은 밀어도 안 움직인다 — 빛을 움직여라

조각 두상 구간(20초)은 푸시인을 걸어도 변화량이 **0.060** 이었다. 정지 플레이트
(0.095)보다 낮다. 알라바스터 표면에 공간 기울기가 거의 없기 때문이다. 푸시인을
0.075 → 0.32 로 4배 키워도 0.226 밖에 안 됐다.

**빛을 움직여서 풀었다**(`face_areas.sweep`). 부드러운 대각선 빛 띠가 왕복하게 한다.
이 영상에서 가장 잘 나온 생성 클립(V4, 5.106)이 한 일이 정확히 그것 — "빛 한 줄이
석재를 쓸고 지나간다" — 이라 톤도 어긋나지 않는다. 0.060 → **0.319**. 생성이 아니라
코드라 비용도 0 이다. 마무리 QR 구간에도 같은 도구를 썼다(0.200 → 0.361).

### 5. 국소 스크림이 배경까지 눌러 놓는다

`band_scrim` 은 "글자 자리에만" 까는 도구인데, 화면 34~39% 를 alpha 190~214 로 덮으면
**그 안의 배경 움직임이 같이 죽는다.** Y1 0.352, Y2 0.200 의 원인이 이것이었다.
띠를 좁히고 alpha 를 낮추니 0.397 / 0.359 가 됐다. 글자는 이미 `shadow=` 를 갖고 있다.

### 6. 실사를 잘라서 채우면 증거가 사라진다

9:16 전면으로 깔면 세로가 아닌 원본은 가로가 21~63% 잘린다. 수료증 제목이 잘리고,
학회 스크린의 원장명이 날아가고, 상담 장면에서 부위를 짚는 손이 화면 밖으로 나갔다.
**잘린 부분이 곧 증거인 사진**은 원본 비율 그대로 띠에 앉힌다(`panel_scene`).
DELIVERY.md §5 에 배율 표가 있다.

### 7. Cormorant 숫자 함정은 `KR0062025` 만의 문제가 아니다

`100` 을 Cormorant Light 200px 로 찍으니 화면에서 **`IOO`** 로 읽혔다. 올드스타일
숫자라 1 이 소문자 높이로 내려앉는다. 이 서체로는 **숫자를 크게 찍지 마라.**

### 8. 캡슐 단면을 호로 자르면 팩맨이 된다

껍질을 `arc(35°, 340°)` 로 그리고 양끝에서 중심으로 선을 그었더니 파이 조각으로
읽혔다. 잘라 보여 줄 필요가 없다 — 껍질을 밝은 링으로 두르고 안쪽에 알갱이를 담으면
'담겨 있다'가 그대로 읽힌다.

### 9. AI 클립이 의료 내용을 설명하게 두지 마라

E3 에 V6(생성 클립, 구슬 더미처럼 보인다)을 깔고 그 위에 "단계적으로 방출되는
구조입니다" 를 얹었다. 화면 표기는 `개념도` 였지만, 보는 사람은 **그 구슬을 캡슐로
읽는다.** 설계서 §4-③ 이 금지한 바로 그 경우다. 클립은 바탕으로 물리고 캡슐은
`capsule_dia.closeup` 이 직접 그리게 고쳤다.

## Seedance 2.5 실측 (2단계 기록에 더한다)

- **길이는 4~30초를 받는다.** 긴 베드를 블록 길이와 같게 생성하면 감속이 사라진다.
  5초를 16초로 늘리면 움직임이 배속만큼 깎이고(0.544 → 0.17) 거기에 감광까지 걸면
  v1 의 실패 지점이다. `clip_bed` 가 감속 1.6배를 넘으면 예외로 멈춘다.
- **480p 는 초당 정확히 3크레딧** (5초=15 · 10초=30 · 16초=48).
- 요청 N초 → 출력 **N + 0.04초 / 480×854 / 24fps**. 길이 요청은 정확히 반영된다.
- **`minterpolate` 는 예외 없이 마지막 한 장을 버린다** — 30편 전부 복제 1장이 필요했다.
- **12편 동시 제출은 429 `rate_limit_reached` 로 막힌다.** 8편씩 나눠 보낼 것.
- **"빛이 번져 나온다" 류 프롬프트는 어두운 데서 시작한다.** `blackdetect` 가 1.03초를
  잡았다. 첫 프레임부터 밝아야 하면 프롬프트에 그렇게 적어라
  ("already lit and clearly visible from the first frame").
- 약한 프롬프트: "입자가 퍼진다"(0.363). 같은 참조에 **빛 사건을 같이** 주니 2.060.

## 파이프라인 함정

- **`clips.py --convert` 에 `--keys` 를 빠뜨리면 보고서의 모든 클립을 다시 변환한다.**
  기존 V1~V10 은 150프레임으로 굳어 있는데 원본 길이(5.04초→151장)로 바뀌어 파일럿
  검사가 깨진다.
- **병렬 변환은 `clip_report.json` 을 같이 쓰면 안 된다.** 마지막 프로세스만 남는다.
  `convert_par.py` 가 키마다 `_meta_<key>.json` 에 쓰고 `--merge` 로 접는다.
  순차 25분 → 병렬 2분.
- **`probe_motion.py --step` 을 키우면 실제보다 낮게 나온다**(E2: step1 0.275,
  step3 0.205). 부드러운 움직임은 프레임 간격을 벌려도 차이가 비례해 커지지 않는다.
- 렌더 속도 **프레임당 0.09초**. 12청크 병렬로 10,800프레임에 3분 30초.
  프로세스마다 클립 캐시가 최대 1.6GB 이므로 12병렬에 20GB 를 본다.
