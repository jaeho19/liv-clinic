## 1. 확정할 제작 방향

작은 건축 모형처럼 접힌 네 개의 쇼룸이 열리고, 그 안에서 울쎄라·써마지·덴서티·악센트 프라임의 이름이 등장한다. 가상의 문을 지나면 실제 리브성형외과의 로비와 김수영 원장 소개로 이어진다. 핵심 문장은 **“리프팅, 이 건물 4층에서.”**다.

화려한 공간 변환이 시선을 잡고, 실제 장비·의료진·공간 사진이 그 관심을 병원 인지로 연결한다. 실제 로비의 곡선 벽, 월넛, 석재, 간접조명을 가상 쇼룸의 디자인 기준으로 삼는다. 가상 도시를 실제 자은빌딩 외관처럼 제시하지 않는다.

6분 전체를 보는 관객뿐 아니라 중간 10~30초를 보는 사람도 대상이다. **30초짜리 독립 장면 12개**를 연결하며, 병원명과 4층 안내는 모든 구간에 유지한다. 음성 없이도 내용을 이해할 수 있도록 만든다.

첫 30초가 내부 검수를 통과하면 나머지 장면 제작을 계속한다. 사용자가 새 창에서 제작을 지시한 뒤에는 이 30초를 별도 승인 단계로 삼지 않는다. 중간 결과와 수정 사항은 간단히 공유한다.

## 6. 화면과 움직임의 기준

- 팔레트: 더스티 로즈 `#b4988d`, 브라운 `#6d4e42`, 오프화이트 `#f6f6f6`, 본문 차콜 `#575756`. 실제 로비의 월넛과 석재를 함께 사용한다.
- 안전 여백: 사방 72px 이상. 상단 병원명, 중앙 시각 연출과 장비명, 하단 4층 안내를 고정된 위치에서 운용한다.
- 1080×1920 시작값: 제목 88~110px, 장비명 80~96px, 보조 문장 48~56px, 고정 병원명·층수 44~52px. 긴 문장은 두 줄 이내로 나눈다. 현장 가독성에 따라 조정한다.
- 글자는 Pretendard 또는 맑은 고딕 등 실제 한글 폰트로 편집 단계에서 만든다. AI 영상에 병원명·장비명·전화번호·QR을 그리게 하지 않는다.
- 장비별 주된 이름은 최소 8초 연속 유지한다. 글자 등장 모션은 약 0.4~0.7초, 그 뒤에는 안정적으로 읽히게 한다.
- 인물은 실제 사진 레이어를 사용한다. 프레임 이동·자르기·약한 확대를 적용하며 표정, 손동작, 진료 장면, 발언을 생성하지 않는다.
- I02~I07의 800px 가로 사진은 세로 화면 안의 사진 패널로 배치한다. 고해상도 I01은 실제 구도 안에서 천천히 이동할 수 있다.
- 실제 인테리어는 2D 사진 이동과 마스크로 연출한다. 방을 새로 만들거나 병원 구조를 확장하는 생성은 하지 않는다.
- AI 생성은 가상 건축·커튼·리본 등 배경에 집중한다. 피부가 당겨지거나 전후 효과가 발생하는 장면으로 연결하지 않는다.
- 장비 PNG는 로고·화면·본체 형태를 유지한다. 카메라가 도는 것처럼 가짜 측면을 새로 만드는 대신 사진 전체 이동·크기 조절로 연출한다.
- QR은 실제 URL로 인코딩한 이미지를 사용한다. 최종 프레임 기준 약 320px, 충분한 여백, 마지막 12초 고정. 최종 영상 프레임에서 재스캔한다.

## 7. 생성량과 견적

6분 중 **독립적인 AI 배경 영상은 8개×6초=48초**다. 나머지 312초는 기존 사진·장비 이미지·타이포그래피·편집 모션으로 구성한다. 짧은 영상을 6분으로 늘려 반복 재생하는 방식이 아니다. 각 30초 장면 안에 4~5개의 정보·구도 변화가 있다.

| 작업 | 모델·설정 | 수량 | 2026-09-18 읽기 전용 견적 |
| --- | --- | --- | --- |
| 공간 시작 이미지 | Nano Banana Pro, 9:16, 2k | 8개 | 2크레딧×8 = 16 |
| 이미지 기반 공간 영상 | Kling 3.0, 9:16, 6초, Pro, sound off | 8개 | 10.5크레딧×8 = 84 |
| 최초 생성 합계 | 위 설정 기준 | 16개 작업 | **100크레딧** |
| 재시도 포함 작업 목표 | 우선 4개 배경까지 재시도할 여유 | 계획값 | **150크레딧 이내** |

견적 API만 호출했으며 생성 비용은 발생시키지 않았다. 단가·지원 설정은 제작 시 다시 확인한다. 150은 이 실행안의 비용 목표이고 현재 잔액 전부를 쓰라는 지시가 아니다. 동봉한 새 창 지시문은 합계 150크레딧을 제작 상한으로 명시한다. 초과가 예상되면 기존 이미지와 native 모션으로 해당 배경을 대체한다. 자동 충전·구독 변경은 하지 않는다.

배경 실패는 컷마다 한 차례 재시도를 우선 한도로 두고, 여전히 형태가 불안정하면 합격한 시작 이미지의 마스크·패널 이동으로 완성한다. 필요한 장면을 만들기 위해 모든 배경의 변형 버전을 무제한 생성하지 않는다.

## 8. 새 창의 실행 순서

1. 이 문서와 두 JSON을 읽고 파일이 존재하는지 확인한다. 사용자에게 자료를 다시 설명하거나 업로드하도록 먼저 요구하지 않는다.
2. Higgsfield 연결과 해당 워크스페이스를 확인한다. D01과 I01 등은 이미 `assets/`에 있다. 클라우드 ID가 만료되거나 접근되지 않으면 로컬 사본을 사용한다.
3. `video-editing`과 `motion-craft` 스킬을 읽는다. 렌더 환경의 `higgsedit --capabilities` 또는 `--help`, 설치된 `types/fable.d.ts`에서 실제 지원 API를 확인한다.
4. 이미지·영상 모델의 현재 파라미터와 같은 설정의 견적을 조회한다. 허용하지 않는 필드를 추정해 넣지 않는다. 배경 시작 이미지 G01과 6초 영상부터 만든다.
5. 시작 이미지와 영상의 중앙 여백, 접힘 구조, 과도한 흔들림, 마지막 정착 프레임을 점검한다. 실제 장비나 인물은 배경 생성물에 포함하지 않는다.
6. 한국어 제목과 기존 자료를 얹어 첫 30초 M01을 편집한다. 0·3·6·13·21·27·29.9초 프레임과 전체 재생을 점검한다.
7. 기준에 맞으면 G02~G08을 만들고 M02~M12를 편집한다. 자막·사진 레이어를 재사용하되 소재·구도·문구의 변화는 장면별로 유지한다.
8. 360초 마스터와 낮은 용량의 프리뷰를 내보낸다. ffprobe로 길이·프레임레이트·크기·코덱을 확인하고 시작·중간·끝 및 모든 전환을 재생 검토한다.
9. 실제 사용 에셋, 생성 job ID, 프롬프트, 비용, 결과 파일 경로를 기록한다. 영상·프로젝트를 로컬에 보관한 뒤 결과를 사용자에게 전달한다. 외부 공개나 모니터 송출은 별도 작업이다.

### 도구 연결 시 주의할 기술 사항

- JSON의 `local_assets[].higgsfield_media_id: null`은 아직 업로드하지 않았다는 뜻이다. 여기에 임의 UUID를 만들지 않는다.
- 로컬 자료를 Higgsfield 참조로 보내야 할 경우 `media_upload`로 업로드 URL을 받아 파일 바이트를 PUT하고, 성공 후 `media_confirm`으로 확정한다. `media_upload_and_confirm`은 ChatGPT 첨부용 도구이므로 임의 로컬 경로를 넣지 않는다.
- 일반 참조 이미지 ID는 생성 도구의 `medias`에 전달한다. 현재 공통 입력의 정식 role은 `image`/`start_image` 등이다. 모델 내부의 `image_references` 같은 키를 공통 role로 추정 입력하지 않는다.
- Element를 실제 생성에 쓰기로 결정한 경우 프롬프트에 `<<<709fba3c-1e18-4e12-9384-dd687bcbb880>>>` 형태를 쓴다. `@이름` 또는 Element UUID를 일반 media ID로 넣는 방식은 사용하지 않는다. 본 영상 기본안은 인물 생성 없이 D01 사진 편집으로 완성한다.
- Kling 3.0은 생성한 시작 이미지 job ID 또는 업로드 이미지 ID를 `medias: [{role: "start_image", value: "실제 ID"}]`로 전달한다. Element를 함께 쓰더라도 시작 이미지가 필요하다.
- 확인된 Nano Banana Pro 설정: `resolution: "2k"`, `aspect_ratio: "9:16"`. 확인된 Kling 설정: `duration: 6`, `mode: "pro"`, `sound: "off"`, `aspect_ratio: "9:16"`. 생성 도구의 현재 입력 스키마를 우선한다.
- `get_workflow_instructions`의 현재 경로는 웹사이트용이다. 영상 워크플로가 있다고 가정해 호출하지 않는다.
- 원격 `sandbox_exec`는 호출마다 임시 환경이다. 입력 다운로드·프로젝트 빌드·렌더·결과 저장을 한 실행 안에서 처리하거나, 다음 실행에 필요한 파일을 확정된 저장소/로컬에 내려받아 전달한다.
- 기존 편집 프로젝트를 덮어쓰지 말고 `liv-lifting-city-01`이라는 새 작업으로 만든다. Higgsedit 편집 파일이 있다고 호스팅된 편집기 URL까지 있다고 보고하지 않는다.

## 9. 프롬프트와 편집 데이터

## 10. 완료 판정과 납품

- 1080×1920, 30fps, 360초로 완성하고 검은 프레임·잘린 글자·오탈자가 없다.
- 전 구간에 리브성형외과와 4층 안내가 보인다. 어느 장면에서 들어와도 병원과 상담 주제를 이해할 수 있다.
- 네 장비명이 M01·M06·M10·M12에 반복된다. M02~M05는 각각 하나의 장비를 충분히 읽히게 한다.
- 원장 사진은 D01 또는 실명이 출처로 확인된 사진이다. AI가 발언·진료 행동·치료 결과를 새로 만들지 않는다.
- 장비명과 실제 사진을 대조했다. 악센트 프라임을 울쎄라피 프라임과 혼동하지 않는다.
- M12의 마지막 12초에서 최종 QR이 실제로 스캔된다. 현장 플레이어의 반복 재생과 2~3m 거리 가독성은 현장 확인 항목으로 남긴다. 현장 검증을 한 것처럼 보고하지 않는다.
- 생성 시도·실사용 비용을 기록하고 새 창 지시문의 150크레딧 상한을 지킨다.

예정 납품 파일:

```text
output/lifting-city/
  renders/LIV_lifting_city_01_1080x1920_6min_silent.mp4
  renders/LIV_lifting_city_01_preview.mp4
  edit/                    # 편집 소스와 재현 가능한 프로젝트
  generation_log.json      # 실제 job ID, 파라미터, 비용, 결과 경로
  qc_report.md             # 수행한 확인과 현장 확인 항목
```

촬영 전후 비교, 효과 보장, 다른 병원과의 우열, 확인되지 않은 인증·수상 문구는 이 영상의 구성에 없다. 의료광고 송출에 필요한 최종 문구와 절차는 실제 게시 매체에 맞춰 검토할 사항이며, 이 문서가 심의 완료를 의미하지 않는다.
